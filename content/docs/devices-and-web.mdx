description: Open Cocurdex in a browser on this computer, pair another device, hand work to another computer, or use the iOS and Android app on the same daemon.

The daemon on this computer is the host. The desktop app starts it, and so does a [headless install](/docs/getting-started/#headless-install) that has no desktop app. **Settings → Devices** lets you use that host from a browser — on this computer, or on another device you pair — and from the iOS and Android app. **Other computers** on that page is the other direction: computers this one can open and hand work to.

Nothing here replaces the daemon. The browser and the phone app talk to the Cocurdex instance already running on the machine; that connection does not create a second workspace or a cloud account.

Opening the desktop app starts that daemon. The CLI packaged with the app, and the CLI from a headless install, start it when nothing is listening. **Keep running in the background** (**Settings → General → Daemon**) keeps the desktop app's daemon running after you quit and starts it at login, so the browser and paired devices keep working with the desktop window closed. A headless install uses `cocurdex daemon background on` for the same idea. See [Daemon](/docs/providers-and-settings/#daemon) and [Headless install](/docs/cli/#headless-install).

## Open in browser (this computer)

**Settings → Devices → Open in browser** loads the local web client against the same workspaces and sessions as the desktop app.

The CLI prints that URL:

```bash
cocurdex web
```

The daemon must be running to serve the client. A headless install serves this same client. The URL includes a local token; treat it like access to this machine.

## Remote access

Off by default. **Allow remote devices** lets paired devices on your LAN or Tailscale tailnet connect to this computer. Only paired devices can connect, with the permissions you grant.

- The UI lists reachable **LAN** and **Tailscale** addresses when they exist.
- You can set the listen **port** (default is shown in the field).
- **Keep this computer awake** stops idle sleep while remote access is on, so a phone can reach it away from your desk. It stays in effect while the daemon is running, including after you quit the desktop app with **Keep running in the background** on. A closed laptop lid still puts it to sleep.

Traffic between a paired device and this computer is end-to-end encrypted. To reach the computer away from its network, install Tailscale on both devices, or use a [relay](#relay).

From the CLI:

```bash
cocurdex host status
cocurdex host remote enable [--port <port>] [--keep-awake on|off]
cocurdex host remote disable
```

### Relay

**Relay** reaches this computer from anywhere through a `cocurdex-relay` service. The relay forwards end-to-end encrypted traffic and cannot read it. It takes effect while remote access is on.

| Setting | Meaning |
| --- | --- |
| **Relay address** | The official Cocurdex relay (**Use official**) or a self-hosted `cocurdex-relay` address. Leave empty to turn the relay off |
| **Invite credential** | The credential from the relay operator. Pasting it fills in the relay address. The official relay admits only invited computers; a self-hosted relay without invites does not need one |
| **Relay only** | Accept connections only through the relay and stop listening on local network ports |

**Status** shows **Online** (with the round-trip in milliseconds when it is known), **Connecting**, **Offline**, **Off**, or **Turn on remote access to connect**. Without **Relay only**, the LAN and Tailscale listener stays on. Paired devices use a direct address when one answers and fall back to the relay.

```bash
cocurdex host relay set [official|<url>] [--relay-only on|off] [--credential <file>]
cocurdex host relay off
cocurdex host traffic [--reset]
```

`host traffic` prints how much remote traffic this computer has sent and received since the counter started. `--reset` clears that counter.

### Phone notifications

A push gateway (the `cocurdex-push` service) lets this computer notify paired phones when an agent asks for approval, asks a question, or has a plan to review, and when a turn finishes or fails. Phones that allow notifications register themselves. Each notification is encrypted to the phone's key, so the gateway, Apple, and Google see only ciphertext.

```bash
cocurdex host push set <url>
cocurdex host push status
cocurdex host push off
```

## Pair a device

**Pair a device → Create pairing code** creates a one-time code, a QR code, and pairing links. Links are listed most reachable first: the relay while it is online, then Tailscale, then LAN. A headless install has no Settings screen. `cocurdex host pair` creates the same code, and `cocurdex host approve` types the safety code.

- **iOS or Android app:** choose **Pair a Computer**, then **Scan to Pair** and scan the QR code, or **Paste Pairing Link** and tap **Pair**. The app adds that computer, selects it, and opens **Approve on Computer**. That screen shows the six-digit **Safety Code** to type on the computer. When the computer allows the phone and the connection is live, the status reads **Paired** and the screen closes. You then continue on **Assistant**. A paired phone learns every address the computer reports and switches to the one that answers.
- **Browser on another device:** open the pairing link, or paste it on the **Pair** screen. A browser on another device connects only through a [relay](#relay), so turn one on first.

If no address of the computer answers — a different Wi-Fi network, or access-point isolation — **Pair** and the scan screen show **Can't reach the computer. Check that it is online and reachable on your network or through its relay.**

| Setting | Meaning |
| --- | --- |
| **Device name** | Label shown in the paired-devices list |
| **Code valid for** | 10, 30, or 60 minutes |
| **Permissions** | What the new device may do (below) |

Turn remote access on first if you want a link the other device can open. Codes work once. Pending pairings appear under **Pending pairings** until they expire or you **Cancel** them.

Redeeming a code does not connect the device yet. It stays pending until this computer approves it. The new device shows a six-digit **safety code**. On the computer, **Allow &#123;name&#125; to use this computer?** asks you to type that code. **Allow** connects it. **Deny** revokes it. Closing the dialog leaves the request pending; **Paired devices** lists it as waiting, without the code, so the code has to be read off the device. Five wrong codes revoke the device. The request expires after 10 minutes.

A browser that is waiting shows **Waiting for approval** and the same code, and opens the workspace once the computer allows it. On the phone, **Approve on Computer** shows the **Safety Code** as soon as you scan or paste a pairing link. The computer list shows **Waiting for approval on the computer** for that computer until then, and the phone keeps checking, so **Sessions** fills in shortly after **Allow**. Under the **Safety Code**, the phone shows a live status. While it waits, a spinner appears next to **Waiting for approval on the computer**. If the phone has no network connection, the status reads **Unreachable**. After the computer allows the device and the connection is live, it reads **Paired**. The screen then closes and the phone connects. If the request expired or was revoked, it reads **Pairing expired or was revoked. Pair again from your computer.** A revoked phone's computer row reads **Access revoked**. Approve from the dialog, from **Paired devices**, or with `cocurdex host approve` (below).

A paired device with **Manage devices** can approve or revoke other devices. **Host administration** (change app settings) stays on this computer and cannot be granted.

```bash
cocurdex host pair --label "My phone" [--scopes read,interact,approvals] [--ttl <minutes>]
cocurdex host pairings
cocurdex host pairing cancel <pairing-id>
```

Default CLI scopes are `read`, `interact`, and `approvals`.

## What a paired device may do

You choose scopes when pairing.

| Permission | Lets the device |
| --- | --- |
| **Read** | See sessions, messages, notes, issues, and decks |
| **Interact** | Send messages, stop sessions, and edit notes, issues, and decks |
| **Approvals** | Answer permission requests, questions, and plan approvals |
| **Start work** | Start sessions, teams, and script runs; change or run MCP servers; message a session that runs tools without asking, and switch it into such a mode. The phone labels this **Start tasks** |
| **Read files** | Read workspace files, diffs, and Git status, and outline a PowerPoint file inside a workspace |
| **Write files** | Edit workspace files, stage, commit, and write a deck export into a workspace |
| **Destructive Git** | Discard changes, check out branches, and push |
| **Credentials** | Manage provider logins and API keys, and view MCP servers |
| **Manage devices** | See, approve, and revoke paired devices |

**Start work** is what a paired device needs before it can drive an agent that does not ask. That includes a Pi session that can run tools (a Pi chat does not), and a permission mode that approves every tool call. Changing the mode away from the ordinary or plan choice needs the same permission. Changing the model or the reasoning effort does not. On the phone the composer then says **This agent runs commands without asking for approval. Messaging it needs the “Start tasks” permission for this device. Grant it on the computer.** A paired browser shows the refusal in the session.

**Paired devices** lists each device with its permissions, when it was last seen, and a six-digit **safety code**. The phone shows the same **Safety Code** on that computer's detail screen. Matching codes mean no one swapped either key. If they differ, revoke the device and pair again. A device marked **Paired before encryption** must be revoked and paired again.

**Edit access** changes an active device's permissions and reconnects it. Revoke a device at any time from **Paired devices**. It disconnects immediately and must pair again to reconnect.

```bash
cocurdex host devices
cocurdex host approve <device-id> --code <safety code>
cocurdex host revoke <device-id>
cocurdex host scopes <device-id> --scopes <list>
cocurdex host audit [--limit <n>]
```

**Access log** records pairing, revoke, relay, and remote-access changes on this host.

## Other computers

**Settings → Devices → Other computers** lists computers this one can open and hand work to. The group says **Computers this one can open and hand work to. Pair with a link created on the other computer.** With none yet, it says **No other computers paired yet.**

Pairing runs in one direction. On the other computer, this one shows up as an ordinary paired device under **Paired devices**. An **Other computers** row on that machine is a separate pairing started there.

On the other computer, open **Settings → Devices** and create a pairing that allows **Start work** (`execute`), together with **Read** and **Interact**. Copy its pairing link. From the CLI on that computer:

```bash
cocurdex host pair --label "<this computer>" --scopes read,interact,execute
```

Add any further scopes you want on that same `--scopes` list. `execute` is what this computer needs before it can hand work over. The default scopes `read,interact,approvals` do not include it. Turn remote access on first when the other computer should offer a link this one can open. See [Pair a device](#pair-a-device).

On this computer, **Pair a computer** opens **Pair another computer**. Paste the link into **Pairing link** (the placeholder is **Paste the pairing link from the other computer**) and choose **Pair**. The dialog says **On the other computer, open Settings > Devices, pair a device with Start work allowed, and copy its link.** After it pairs, the dialog shows the safety code and **Paired with &#123;name&#125;. Check that the safety code matches on both computers.** Choose **Done** to close it.

The same step from the CLI, run on this computer:

```bash
cocurdex host remotes pair <pairing link> [--label <name for this computer>]
```

`--label` is the name the other computer shows for this one. Omit it and that name is this computer's hostname. The command prints `Paired with <name> (<host id>)` and `Safety code: <code>`. While the pairing is still pending it also prints `On <name>, approve this computer: cocurdex host approve <device-id> --code <code>`.

While the row says **Waiting for approval**, approve on the other computer when the safety code matches. The dialog says **On &#123;name&#125;, open Settings > Devices and approve this computer when its safety code matches.** Approve from that dialog, from **Paired devices** on the other computer, or with `cocurdex host approve <device-id> --code <code>`.

If **Read**, **Interact**, or **Start work** is missing, the dialog says **To hand work to &#123;name&#125;, it must also allow: &#123;scopes&#125;.** The scope names are the permission titles, such as **Read**, **Interact**, and **Start work**. The CLI prints `To delegate work there, <name> must also grant: <scopes> (cocurdex host scopes <device-id> --scopes ...)`, with the missing scope ids, such as `read, interact, execute`.

Each row shows the status and the safety code, as **&#123;status&#125; · Safety code &#123;code&#125;**:

| Status | In `cocurdex host remotes list` |
| --- | --- |
| **Checking** | `unknown` |
| **Connected** | `connected` |
| **Waiting for approval** | `pending` |
| **Offline** | `offline` |
| **Access removed** | `rejected` |

`list` columns are `hostId`, `name`, `status`, `scopes`, `safetyCode`, and `pairedAt`. With no computers paired, it prints `No records`.

**Open** opens that computer in its own desktop window. The window title is the computer's name, and the window runs this same app against that computer's daemon. **Open** belongs to the desktop app. The local web client leaves it out, and a window that is already showing another computer leaves it out too. **Open** stays hidden while the status is **Access removed**.

**Remove** revokes this computer on the other machine and stops tracking work delegated there. The confirmation title is **Remove &#123;name&#125;?** and the text is **This computer loses access to it, and work delegated there is no longer tracked here.** The CLI prints `Removed <name>`.

```bash
cocurdex host remotes list [--json]
cocurdex host remotes pair <pairing link> [--label <name for this computer>] [--json]
cocurdex host remotes workspaces <computer> [--json]
cocurdex host remotes remove <computer>
```

`<computer>` is the host id or the exact name. When several computers share a name, pass the id. The CLI then says `Several paired computers are named "<name>"; pass its id`. No match says `No paired computer matches "<name>"`. `workspaces` prints that computer's workspace `id` and `name`.

Handing an assistant's work to one of these computers is [On another computer](/docs/assistants/#on-another-computer). The iOS and Android app does not list **Other computers** and does not open these windows.

## Native app

The iOS and Android app has four tabs: **Sessions**, **Issues**, **Notes**, and **Settings**. The tab bar floats just above the bottom edge. The app opens on **Assistant**. The title on the **Sessions** tab switches among **Assistant**, **Work**, and **Chat**, with the descriptions **Talk to your assistants**, **Run workspace tasks**, and **Chat with a model**. **Settings** includes **Computers**, which lists paired computers. **Assistant**, **Work**, **Chat**, **Issues**, and **Notes** are for the computer named in the toolbar.

On Android, the launch screen uses the same mark as the desktop app, in light and dark. It stays until the first screen has its data, and hides after 3 seconds if that data has not arrived.

With no computer paired yet, those tabs show **No Computers** and **Pair a Computer**. After you pair, open the computer name in the toolbar to switch hosts, or choose **Pair a Computer** to add another.

Each computer row shows **Connected** with the round-trip in milliseconds, **Checking**, **Unreachable**, **Waiting for approval on the computer**, or **Access revoked**. While this phone is waiting for the computer to allow it, the row stays on **Waiting for approval on the computer** and keeps checking, so it shows **Connected** shortly after you allow it. A revoked phone shows **Access revoked**. **Unreachable** is for a computer whose addresses do not answer. Open a computer for **Permissions and Connection**, including the **Safety Code**. **Rename** changes the name on this phone only. **Remove This Computer** drops the pairing; if the computer is offline, revoke it later under **Settings → Devices**.

### Assistant

**Assistant** lists two sections for the computer in the toolbar, when they have anything to show:

| Section | Shows |
| --- | --- |
| **Today** | Today's successful routine results that were not silent |
| **Assistants** | The assistants on that computer |

Each assistant row shows the latest reply, or **Working** while its home thread is running. With no reply yet, the line is the description. A report the assistant has not answered yet does not replace that line. The row also shows the time of the latest message, a status dot, and a muted bell labeled **Muted** when the assistant is muted. A muted row hides the unread mark. A muted assistant does not notify the phone; what needs you still shows under **Needs you** in **Overview**.

**New assistant** in the header opens **New assistant**. It needs **Interact**. When a model is available, the form opens already filled in: a name no assistant on that computer uses, the default assistant's model when that model is still available (otherwise the first compatible model), and an avatar. Opening it again fetches a new name and avatar. The fields are **Name**, **Description**, **Avatar**, **Model**, **Instructions**, and **Persona** (up to 20,000 characters). **Avatar** has **Shape**, **Expression** (**Calm**, **Happy**, **Wink**, **Sleepy**, **Curious**), **Color**, and **Custom emoji**. **Model** shows the filled-in model. **Default** is still in that list; choosing it lets **Create** pick a model the same way. **Create** opens the new home thread and asks the assistant to greet you. **Couldn't save. Try again.** appears when the save fails. With no model available, the form does not open and the screen says **Set up a model on your computer to create an assistant**. If a draft cannot be prepared, it says **Couldn't prepare a new assistant**, with **Try Again**.

Long-press a row, with **Interact**, for **Edit**, **Pin** / **Unpin** (not on the default), **Mute** / **Unmute**, **Duplicate**, and **Delete**. **Edit** opens **Edit assistant** with the same fields, and **Save** returns to the list. **Duplicate** adds **copy** to the name and opens the copy's thread. **Delete** asks **Delete "&#123;name&#125;"?** and says **This deletes the assistant and its conversation. Its memories stay in the memory store.** A failed action says **Something went wrong. Try again.**

Tap an assistant to open its home thread. If that thread is still empty and the phone has **Interact**, the assistant writes its greeting then. **Overview** in the header opens a page for that assistant:

| Section | Shows |
| --- | --- |
| **Needs you** | What is waiting or has failed for this assistant. Hidden when there are none. A routine that needs you or is blocked is labeled **Needs you**, including when the routine is silent |
| **Delegated work** | Work this assistant handed to a workspace that is still **Running** or **Idle**. The line under a title is the workspace and that status. With none yet, the footer is **Work delegated by this assistant will appear here.** If the list cannot be loaded, the footer is **Work couldn't load.** |
| **Recent results** | Delegated work that has finished. The line under a title is the workspace and **Turn completed**, **Failed**, **Cancelled**, **Interrupted**, or **Archived**. Hidden when there is none |
| **Routines** | A read-only list. The line under a name is **Next run:** and the time, **Paused**, **Paused after failures**, or **No next run scheduled**. Tap a row to open its latest run when it has one. The footer is **Routines run on the connected computer while its background service is online.** If the list cannot be loaded, the footer is **Routines couldn't load.** |
| **Context and resources** | **Notes** and **Issues**, which open those tabs |

The overview header shows the avatar, the name, and the description. With no description it says **Coordinate work, keep context, and follow through.**

Tap a **Needs you** row or a result to open that session. With no assistants yet, the screen says **No assistants yet** and **Assistants keep context, follow up on work, and report back to you.** **New assistant** is on that screen, and it needs **Interact**. If the phone cannot reach the computer, it says **Can't reach** that computer, with **Try Again**.

Assistant threads stay out of **Work**. In a thread, a posted brief is marked **Today's brief**, and a posted routine result is marked **From routine** plus the routine's name. Each of those is its own turn. A delegated report the assistant has not answered yet is one muted line, not a bubble: the session title, the outcome (**Done**, **Needs you**, **Blocked**, **Failed**, **Cancelled**, or **Interrupted**), and **waiting for the assistant**. After the assistant answers, the reply shows **Based on** and the session title. The title opens that session.

**Issues** and **Notes** can be edited when the phone was paired with **Interact**. See [Notes and issues](/docs/notes-and-issues/#on-the-phone).

On **Work**, **Display Options** matches the desktop controls that fit on a phone: **Group By** (workspace, status, agent, last updated, or none), **Sort By**, filters for agent, status, and environment (local or worktree), **Sessions per Group**, and **Archived Sessions**. When **Group By** is not **None**, the list is not being searched, and more than one group is showing, a row of chips under the title lists **All** and every group of that grouping, including **Pinned** when a session is pinned. **All** has no count. Each other chip shows that group's session count. Choosing a group shows only that group, in full, with no section header and no footer to show more. The choice is kept, and returns to **All** when **Group By** changes. The row hides while searching, and when the list is ungrouped. **Pin** keeps a row at the top. A row's menu can **Rename**, **Fork Session**, **Mark as Unread**, **Archive**, or **Delete**. **Search sessions** filters the list. A child session rolls its state up to the root row:

| Status | Meaning |
| --- | --- |
| **Needs you** | A permission, question, or plan is waiting |
| **Running** | The session is still working |
| **Unread** | A result is finished and not yet opened |

The line under the title shows the model name, or a run status when that is more relevant — for example **Waiting for your approval**, **Has a question for you**, **Plan ready for review**, **Working…**, **Connecting…**, **Working in the background**, or **Finished**. A failed run shows **Run failed**.

If the phone cannot reach the computer but already has a list, it keeps that list and shows **Can't reach** the computer's name. **Showing the last update.** With nothing loaded yet, the screen is **Can't reach** that computer, **Check that the computer is awake and online, and reachable on your network or through its relay.**, and **Try Again**. A computer with no sessions shows **No Sessions** — **Sessions you start on** that computer **appear here.** A search with no matches shows **No sessions match** the query.

### Start a session

On **Work**, the toolbar shows a **New session** button when this computer was paired with **Start work** (`execute`). It opens a sheet titled **New session**.

The prompt placeholder is **What should the agent do?**. **Start** stays disabled until that prompt has text, and reads **Starting…** while the session is opening. Under **Run on**:

| Row | Opens |
| --- | --- |
| **Workspace** | Workspaces on this computer |
| **Agent** | **Agent**, **Model**, and **Mode** |

Both pickers push inside the sheet. **Role** lists roles saved on the computer; picking one fills in its agent, model, and permissions. The **Agent** row shows the model and permission mode that **Start** will use. Agents that are not installed on the computer are left out of this list. The line under the rows is **Runs on** the computer's name.

**Workspace** leads with the workspace that had the latest session, and that one is selected until you pick another. **Search workspaces** filters the list. Each row includes a count, such as **1 session** or **3 sessions**. The footer is **Add new workspaces on the computer.**

On **Agent**, a row you can choose says **Ready**. The others say **Not installed on the computer**, **Not supported on the computer**, or **Failed to start on the computer**. **Model** lists models from the providers on the computer (**Models come from the providers set up on the computer.**). If the agent has none, that section says **No provider models for this agent; it uses its own default model.** **Mode** lists that agent's permission modes. An agent with none, such as Pi, says **This agent has no permission modes to choose from.** Mode ids are on [Agents](/docs/agents/#permission-modes).

**Start** creates the session with the workspace, agent, model, and mode on screen, sends the prompt, names the session from that prompt the same way the desktop app does, and opens it. If **Start** fails after that session exists, the sheet says **Couldn't start the session. Check the connection and try again.** Another **Start** on that sheet sends the prompt into the session already created.

### Notes, issues, and transcripts

On **Notes**, the line under a title is a plain-text excerpt of the body. On **Issues**, the identifier is monospace. On the issue screen, each row under **Sub-issues** opens that issue.

Open a work session and the tab bar hides. The back button reads **Sessions**. The header is the session title, with the workspace and model under it. The transcript updates as the agent runs: your messages, the assistant's messages, and tool calls. While the turn is running, an activity line reads **Working…**, **Thinking**, or **Responding**. A tool in progress is named on that line.

An assistant home thread and a chat thread are a conversation. The assistant header is the avatar and the name, with **Overview** beside it. Your messages are bubbles; in an assistant thread they take the avatar color, and replies stay neutral. Tool calls stay out of that transcript, and **Prompts** is not shown.

A chat turn reads **Thinking** before a reply is in the thread, and **Responding** when the turn is still running after a reply has landed. It does not read **Working…**. An assistant turn matches the [desktop home thread](/docs/assistants/#home-thread): the avatar and **Thinking**, then **Still thinking** after 15 seconds, then **Taking longer than usual, hang tight** after 40 seconds. While a tool is running, the line is **Working on it**. The line leaves once the reply is streaming.

A finished chat or assistant reply has **Copy**, which briefly reads **Copied**. A chat reply can show how long the turn took, and **Stopped** when the turn was stopped, joined as **Stopped · 12s**. An assistant reply can show **Stopped** without that duration. An assistant thread shows a time between messages when an hour has passed, or the day has changed.

The assistant composer is a single line, without the model, thinking, or mode controls. While an assistant thread is still empty and not running, it shows **Suggestions**: **What needs my attention today?**, **Send me a brief every morning at 8**, and **What do you remember about me?** Choosing one sends it. While a new assistant is writing its greeting, that list is replaced by the avatar and a shimmering **Working**. The placeholder is **Message** followed by the assistant's name.

In an existing chat, when the phone was paired with **Start tasks**, the composer can switch the model and **Reasoning effort** in place. **New Chat** has the same controls. **Reasoning effort** is shown only when the model offers more than one level. A new chat starts from the latest chat's level when this model still offers it, and otherwise from **Medium**. The placeholder is **Message a model**.

Assistant messages are Markdown. Tables render. A fenced code block shows the language, a copy button, and syntax highlighting. A fenced `mermaid` block renders as a diagram, in the same theme family as the desktop app. If rendering fails, or the phone is offline and the diagram cannot be drawn, the source is shown as a normal code block. Math renders, including inline, display, and table formulas.

Tap an image in the transcript to open a full-screen viewer. Pinch-zoom works on iOS. On Android the viewer is full screen, and pinch-zoom is not available yet. **Close** leaves the viewer.

In a work session, tap a tool-call row to open its detail screen. The header shows the status — **Done**, **Failed**, or **Running** — and the duration in seconds after the call finishes. **Input** and **Output** follow. A long output shows the tail, labeled **Last 64 KB**. When output is on screen, **Copy Output** copies it. If the output cannot be loaded, the screen shows **Couldn't load the output**. The formatting matches the desktop app.

In a work session, the composer placeholder is **Reply to the agent**. **Attach Photo** adds a PNG, JPEG, GIF, or WebP image up to 10 MB. **Send** posts the message. While the session is running and the field is empty, that control is **Stop**. Sending and stopping need the **Interact** permission from pairing.

A file link in the transcript, or a file a tool call names, opens a preview. Markdown can switch between **Show Preview** and **Show Source**. In **Show Preview**, the Markdown can be selected with the system selection toolbar, and a code block keeps the copy button in its header. **Copy Contents** copies the text. A long file says **Showing the first 512 KB of this file.** A binary file says **This file can't be previewed.** A path outside the computer's workspaces says **This file is outside the computer's workspaces.**

**Jump to latest** and **Jump to first message** skip a long transcript. **Jump to latest** shows when the latest message is below the visible area. A short thread that already fits does not show it. The header menu's agent settings show the model, reasoning effort, fast mode, and — when the agent has them — collaboration mode and variant, plus the session's MCP servers. **Save as Role…** stores the current setup on the computer. In a work session, a finished reply has **Copy**, which briefly reads **Copied**, and **Fork From Here**. It can also show how long the turn took, and **Stopped** when the turn was stopped, joined as **Stopped · 12s**.

When the agent is waiting, a dock at the bottom replaces the composer:

- A permission request, with the choices the agent offered.
- A question. Type **Your answer** and tap **Reply**, or pick an offered choice. The title is **The agent has a question** when the agent did not set its own.
- A plan, titled **Review the plan**. **Approve** accepts it. **Keep Planning** sends the agent back to planning.

Paired without **Approvals**, that dock shows **Approve this on your computer** and **This phone was paired without approval access.** Finish the approval on the computer.
