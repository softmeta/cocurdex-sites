title: Memory
description: Long-term memory in Cocurdex — recall before a turn, save a conversation, and optional encrypted sync across your devices.
---

**Memory** lets Cocurdex recall things you have saved and, when you ask, write a conversation into that store. It is off until you turn it on. Entries live in the local [rsrs](https://rsrs.rs) store (`~/.rsrs`), not in `cocurdex.sqlite`. Nothing is uploaded until you turn on multi-device sync.

Intel Macs have no rsrs build, so memory stays off on those machines. The status line says so.

## Turn it on

Open the composer's **+** menu and choose **Memory**:

| Item | Does |
| --- | --- |
| **Enable memory** | Turn recall and saving on or off |
| **Multi-device sync** | Connect an rsrs account. Off until memory is on and rsrs is installed |
| **Memory settings** | Opens **Settings → Memory** |

The same page installs rsrs when it is missing (**Install**), and **Run doctor** checks the install. **rsrs executable** is optional; leave it empty to use the binary on your `PATH`.

**Settings → Memory** also has:

| Setting | Does |
| --- | --- |
| **Recall for agent sessions** | Adds relevant memories to the prompt before each agent turn |
| **Memory tools for agents** | Gives sessions `memory_recall`, `memory_show`, `memory_remember`, and `memory_policy` |
| **Recall for chat sessions** | Recalls before each chat answer |
| **Save chat turns** | Appends each finished chat exchange to today's memory diary |
| **Save chat sessions on end** | Summarizes a chat session when you archive or delete it |

On a chat session, the brain button beside the composer is **Save to memory**. If that conversation is already stored, the app says so. A failed recall for the current turn is reported on the same control.

## Multi-device sync

Off by default. **Multi-device sync** opens **Connect cloud memory**, where you **Create account** or **Sign in**.

- The username and login password belong to the rsrs account. Cocurdex does not store the password.
- Creating an account shows a **recovery key** once in the dialog. Save it. It decrypts your memories on another device, and neither Cocurdex nor the server can recreate it. You can show it again from **Settings → Memory → Recovery key**.
- Signing in on another device needs the same username, password, and recovery key.
- Records are encrypted on this device before they are uploaded. The page says how many memories are waiting to upload, and when sync fails.
- **Sign out** stops automatic sync and leaves the memories on this device where they are. Signing back in needs the same username, password, and recovery key.

The page links to the Respire site and source for what rsrs is.

## Status

**Settings → Memory → Status** shows the installed rsrs version, or **rsrs is not installed**. An error under that line says why memory cannot be used as usual:

| You see | Meaning |
| --- | --- |
| `Memory is paused in rsrs. Restore it in rsrs before using memory in Cocurdex.` | Memory is paused. Restore it in rsrs before using it here |
| `Memory is read-only in rsrs. Recall is available, but new memories cannot be saved.` | Recall still works. New memories cannot be saved |
| `Local memory has not been initialized. For local-only memory, initialize rsrs with rsrs keygen. For multi-device sync, register or sign in from Settings > Memory > Multi-device sync, or run: cocurdex memory cloud register --user <name> (use cloud signin for an existing account).` | This computer has no memory identity yet |

A recall that reports no session, or that you are not signed in, adds the same identity note.

**Run doctor** checks this install. A pass says `rsrs doctor: <status>`. A failure says `rsrs doctor reported a problem`. The status line `doctor: <status> · <pass> pass · <warn> warn · <fail> fail` is shown only for the rsrs version that was checked. After that version changes, the line stays hidden until you choose **Run doctor** again.

## In the Assistants form

The Assistants sidebar offers **Let your assistants remember**, with **Turn on memory** and **Skip**. Turning it on installs rsrs when it is missing. After you leave that card, the same control is **Long-term memory** in the sidebar footer. See [Assistants](/docs/assistants/).

Which memories an assistant sees still follows **Recall for agent sessions**. When that is on, the thread recalls that assistant's own partition and **About me**, not another assistant's. `memory_remember` writes into that assistant's own partition. A fact about you that every assistant should share uses `about` set to `user`, which is **About me**. **Instructions** and **Persona** on the assistant are separate from this library, and both are included on every turn. See [Assistants](/docs/assistants/#home-thread).

## Browse and edit

**Memory** in the right panel lists what is stored.

| View | Shows |
| --- | --- |
| **Diary** | Memories by day |
| **Tree** | The same entries as a tree |
| **History** | Edits, deletions, and restores |

**Partition** filters to **All memories**, **About me**, or one assistant. The menu is shown only when the installed rsrs can split memory this way. When it cannot, the menu stays hidden, and an assistant's recall or a write that needs a partition fails with `Memory partition support is unavailable; unscoped access was refused.` The assistant does not fall back to searching the whole library. Reading an entry outside the allowed partitions fails with `Memory is outside the permitted partition.` A relation that points outside the partition fails with `Memory relation target was not found in the permitted partition.` A conflict that exists only outside the partition is left alone: `Nothing was saved. The memory provider reported a conflict outside this partition; automatic merging was refused.`

**Filter memories** narrows the list. Select an entry to edit its **Title**, **Content**, or **Tags**. **Delete** asks you to confirm; **Undo** on the **Memory deleted** toast restores it when the installed rsrs can. **History** on an entry lists what changed.

## CLI

```bash
cocurdex memory status [--refresh]
cocurdex memory on | off
cocurdex memory install [--force]
cocurdex memory doctor [--remote] [--check-update]
cocurdex memory recall <query> [--limit <n>] [--project <name>]
cocurdex memory show <id>
cocurdex memory remember --title <title> [--content <text> | --file <path> | <text>] [--importance important|trivial] [--tags a,b]
cocurdex memory list [--partition me|agent:<persona-id>] [--since <date>] [--limit <n>]
cocurdex memory update <id> [--title <title>] [--content <text> | --file <path>] [--tags a,b] [--importance important|trivial]
cocurdex memory forget <id>
cocurdex memory restore <full-id>
cocurdex memory history [<id>] [--limit <n>]
cocurdex memory export <file>
cocurdex memory import <file>
cocurdex memory save-session <session-id> [--force] [--importance important|trivial]
cocurdex memory sync on | off
cocurdex memory cloud register|signin --user <name>
cocurdex memory cloud signout | keys
cocurdex memory policy
```

`cloud register` and `cloud signin` read the password from a hidden prompt (and the recovery key on sign-in). When stdin is not a terminal, they read those secrets from the pipe instead. `cloud keys` prints the recovery key. `memory policy` prints the rules the memory tools follow.

`memory list --partition me` is **About me**. `agent:<persona-id>` is one assistant's own memories. `forget` removes an entry; `history` shows its full id, and `restore` takes that id. `export` writes the whole library as plaintext JSON. `import` reads that file back.
