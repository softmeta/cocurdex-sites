Most Cocurdex configuration lives in the desktop app's **Settings**. This page covers the settings that change how agents and models behave — agent CLIs, providers, MCP, network, git, worktree environments, and devices.

## Agent CLIs

**Settings → Agent CLIs** lists every agent you can pick when starting a session. For each one it shows the detected version and status (**Built in**, **Ready**, **Not installed**, **Update required**, **Update available**, **Login required**), a copyable install command, a docs link, and — for agents that report it — your plan usage. Agents that are not installed are folded under **Not installed (N)** until you expand that group. The agent menu on a new session hides those missing agents; an agent you already selected stays visible if it is later uninstalled. **Update to v…** installs a newer ACP Registry build. Registry agents that support it offer **Log in** and **Log out**. **Add from ACP Registry** installs more agents, or registers one with your own command. See [Agents](/docs/agents/#acp-registry-agents).

```bash
cocurdex agent updates
cocurdex agent update <agent>
cocurdex agent login <agent>
```

**Run limits** on the same page cap how many agent runs execute at once. Delegated runs (teammates and script-run subagents) past a limit wait in the queue; runs you start yourself are never held back.

| Control | Meaning |
| --- | --- |
| **Concurrent runs** | Total agent runs across all sessions (1–64) |
| **Concurrent runs per agent** | Runs of the same agent at once (1–64) |
| **Delegated run timeout** | Minutes after which a teammate or subagent run is stopped; empty means no timeout |

## Providers and models

**Settings → Providers** manages **provider configs**: named service endpoints with credentials and a model catalog. These configs feed the built-in **Pi** runtime and in-session model controls.

A provider config holds:

| Field | Meaning |
| --- | --- |
| Provider id / name | Stable id and display name |
| Base URL | Service endpoint |
| API runtime | `openai-completions`, `openai-responses`, `openai-codex-responses`, `anthropic-messages`, `google-generative-ai`, or `mistral-conversations` |
| Auth | A provider account via Pi OAuth, or an API key managed by Pi. A custom provider pointed at a local or proxy endpoint can leave the key empty |
| Models | Per-model id, display name, capabilities (agent / chat / reasoning / vision), context and output limits, cost per 1M tokens |
| Advanced | Custom headers, compatibility JSON, thinking-level maps |

**Model parameters** on a model row edits the API runtime, context and output limits, capabilities, reasoning, and the advanced JSON. Built-in catalog models can be edited too: the fields you change are kept when the catalog updates, and the row is marked **Edited**. **Reset to default** restores the catalog values. Adding or deleting a built-in model is not offered.

Templates fill the endpoint for common providers; **Import JSON** bulk-loads a provider definition. Manage everything in the UI, then verify from the CLI:

```bash
cocurdex provider list
cocurdex provider models <provider-id>
```

Provider configs and models are also scriptable: `cocurdex provider add|update|login|key|model|default|import|export` — see [CLI](/docs/cli/#providers).

External agent CLIs (`claude`, `codex`, `opencode`, and ACP Registry agents such as `cursor-agent` or `grok`) keep their own authentication — Codex account state under `~/.codex`, for example. Provider configs do not replace that; they give Pi and the desktop a shared model catalog.

A custom, local, or proxy provider with no API key is used the same way for one-shot text as for an agent run. That covers Pi session titles, an assistant's greeting, and a generated commit message.

## MCP servers

**Settings → Connections**, on the **MCP** tab, is the tool servers Cocurdex gives to your agents. The page title is **Connections**. **Apps** and **Skills** are the other tabs. New sessions pick up changes; a running session keeps the tools it already has.

- A **form** (name, local command or remote URL, arguments, environment or headers) and raw **JSON**. The JSON shape is the standard `mcpServers` object.
- Server names may contain only letters, digits, `_`, and `-`.
- **Agents** chooses which agents receive the server. Their own MCP configs are left untouched. Some servers can only be used by Pi — for example one that sets a working directory, runs a command value, or signs in through a Pi provider. The row says so.
- Notion, Linear, and GitHub connections are managed on the **Apps** tab, not assigned to agents here. That row says **This connection is managed in Applications. Choose assistant access there; engine-level MCP assignment does not apply.** See [Applications](/docs/assistants/#applications).
- **Import from other agents** reads servers already configured for Claude Code, Codex, Cursor, OpenCode, or Antigravity, including project configs. You confirm each one. You can also drop or paste JSON.
- **Sign in** when a server asks for it. **Test connection** lists its tools.
- A project server defined in a file on disk is read-only here; edit that file to change it.
- **Advanced → Tool exposure** is **Direct** (every tool on the agent's list), **On demand** (tools load when the agent searches), **Code mode** (Pi calls them from generated code), or **Hidden**.

```bash
cocurdex mcp list
cocurdex mcp import --from codex
```

The rest of the commands are on [CLI](/docs/cli/#mcp-servers).

## Network proxy

**Settings → Network** controls the app's outbound proxy:

| Mode | Behavior |
| --- | --- |
| `system` | Follow system / environment proxy configuration |
| `manual` | Use the HTTP / HTTPS / SOCKS (`allProxy`) URLs and bypass list (`noProxy`) you provide |
| `off` | Direct outbound traffic; no app proxy applied |

Scope notes:

- Applies to Agent subprocesses (including ACP), app and daemon model/API requests, and Chromium network traffic.
- Does **not** change the system proxy and does **not** force the integrated terminal to use these settings.
- Proxy URLs are stored as plain text in app settings and passed to Agent subprocesses — avoid embedding credentials you would not want a spawned CLI to read.
- Restart an active agent session after changing proxy settings so it picks up the new environment.

**Test connectivity** sends one request through the app's outbound path and reports the egress IP, so you can tell whether the proxy is really in use.

## Git

**Settings → Git** picks the agent and model used to generate commit messages. When the commit message is left blank, the selected model writes a Conventional Commits subject from the staged changes. Choose **None** to always type messages yourself.

## Worktree environments

Two layers:

- **Settings → Worktrees**: the root directory for managed worktrees (blank = default location) and whether to fetch remotes before creating a worktree. The inventory lists every checkout Cocurdex created, which sessions use it, and offers delete / new-session actions.
- **Settings → Workspaces → Worktree settings**: per-workspace **setup** and **cleanup** scripts plus **actions**. Setup runs in the background after Cocurdex creates a worktree (for example `pnpm install`), and the session's first turn waits for it; cleanup runs before an unused checkout is removed. Actions are named commands (for example *Dev server* → `npm run dev`) shown in the session's **…** menu, each running in a new terminal tab. **Ask agent** has an agent inspect the repository and propose both scripts for your approval.

The same surface is scriptable via `cocurdex worktree settings` — see [CLI](/docs/cli/#worktrees).

## Devices

**Settings → Devices** opens the same host in a browser on this computer, or pairs another device with scoped permissions. See [Devices and local web](/docs/devices-and-web/).

## Settings assistant

The settings screen has an **assistant** dock: a chat session with the `settings` agent tools. Ask it to "switch to dark mode", "review my notifications", or "what can you change?" and it reads and edits the setting catalog for you — including project worktree setup and cleanup scripts. Changes that need your confirmation are proposed first.

Any main agent session can use the same tools; the optional [`/cocurdex-settings`](/docs/skills/) skill teaches agents to use them well.

## App updates

**Settings → About** shows the installed version and **Check for updates**. Choose the **Stable** or **Test** update channel; Test builds can be unstable, and switching back to Stable may install an older version.

After an update downloads, an **Update available** card offers **Update and Restart**, **Later**, and **View release notes**. Automatic updates only work in the packaged app.

## Diagnostics

**Settings → Diagnostics** (or **Help → Export Diagnostics…**) bundles sanitized app logs and runtime info into a file you can attach to a GitHub issue. Turn on **Verbose diagnostics** to record more detail while you reproduce a problem; logs stay sanitized either way. The same actions are `cocurdex diagnostics export` and `cocurdex diagnostics level debug|info`. `cocurdex daemon health` prints the process, memory, and active work.

## Daemon

**Settings → General → Daemon** shows the local daemon (socket, protocol version, start time). **Start** brings it up when it is stopped. **Restart** replaces a running daemon — use it if notes, issues, decks, or agents stop responding. With **Keep running in the background** on, the status line reads **Running (…) in the background; it keeps running after Cocurdex quits.**

**Keep running in the background** is off until you turn it on. On, the daemon keeps serving the CLI and paired devices after you quit the desktop app, and it starts when you log in: a LaunchAgent on macOS, a Run key on Windows, or an XDG autostart entry on Linux. Off, quitting the app stops the daemon it owns. From the terminal, `cocurdex daemon background on|off|status [--json]` is the same switch. See [CLI](/docs/cli/#daemon-and-workspaces).

## Finding a setting

The settings sidebar has a **Search settings** box at the top. While the box has text, **Clear search** empties it. If nothing matches, the list says **No matching settings**.

Command+F on macOS, and Ctrl+F on Windows and Linux, focuses the box. Escape clears it. Up and Down move through the results, and Enter opens the selected one.

Search matches sections and individual settings, including every shortcut, by title, group, section, and description. It matches both English and 简体中文, so `proxy` and `代理` both work whichever language the interface is using. A setting the current window does not show is left out of the results. Results are grouped by section. Choosing one opens that section. Choosing a setting also scrolls its row into view and highlights it briefly. If that row is not on the page in the current state — the manual proxy fields, while **Proxy mode** is not `manual` — it scrolls to the **Proxy mode** row that reveals them.

## Appearance

**Settings → Appearance** sets the theme (**Light**, **Dark**, or **System**), a color theme preset, and the UI and code fonts.

On the main desktop window, when the system can draw a window material, the page also shows **Translucent sidebar**, on by default: **Let the desktop show through the sidebar.** macOS uses sidebar vibrancy. Windows 11 22H2 or later (build 22621 or newer) uses Mica. Linux, older Windows, the [web client](/docs/devices-and-web/), and a chat window opened with **Open in a separate window** stay solid, and these controls stay hidden. When the system requests reduced transparency, the surfaces stay solid even if the controls are shown.

With the switch on, two sliders appear. Dragging previews the change immediately; the value is saved when you release the slider.

| Control | Range | Default | Meaning |
| --- | --- | --- | --- |
| **Sidebar transparency** | 0–100% | 12% | How much of the desktop shows through the sidebar |
| **Main area transparency** | 0–100% | 10% | How much of the desktop shows through the main area |

**Main area transparency** covers the chat column, the right panel, and the settings content together. The window material follows the theme (**Light**, **Dark**, or **System**). The [settings assistant](#settings-assistant) accepts the same limits as integers: `sidebarTransparency` and `contentTransparency` from 0 to 100 (defaults 12 and 10). They apply only on a desktop host with a window material.

When that material is showing, the editor **Code MiniMap** stays opaque. It uses the same solid surface as the sticky editor chrome, so it does not appear black over the transparent editor.

## Other settings

| Section | Covers |
| --- | --- |
| **General** | Chat layout, transcript view, HTML preview location, send shortcut, follow-up queue/steer, language, notifications (including a completion sound), **Shell command** (install `cocurdex` on your `PATH`), daemon status, **Keep running in the background**, and restart |
| **Appearance** | Theme (**Light** / **Dark** / **System** — parity is a product requirement), color theme presets, UI and code fonts, and a [translucent sidebar](#appearance) when the window supports it |

| **Shortcuts** | Rebindable keyboard shortcuts; `null` override unbinds an action |

| **Roles** | Edit or delete saved agent presets, their avatars and descriptions; see [Agents](/docs/agents/#agent-roles) |
| **Teams** | Reusable [team templates](/docs/teams/#team-templates) |
| **Connections** | **Apps**, **MCP**, and **Skills**. **Apps** connects Notion, Linear, and GitHub for assistants ([Applications](/docs/assistants/#applications)). **MCP** is the tool servers above. **Skills** is the skill manager ([Skills](/docs/skills/)) |

| **Network** | Outbound proxy (above) |
| **Git** | Commit-message model (above) |
| **Worktrees** / **Workspaces** | Managed worktree root and inventory; per-workspace scripts and actions (above) |
| **Devices** | Local web client and paired remote devices; see [Devices and local web](/docs/devices-and-web/) |
| **Archived sessions** | Browse sessions you archived; restore or permanently delete |
| **Open source licenses** | Third-party licenses |
| **About** | Version, update check and channel; see [App updates](#app-updates) |
| **Diagnostics** | Export diagnostics, verbose logging |
