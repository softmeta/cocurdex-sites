Notes and issues are first-class **product records** in Cocurdex. They live in app-owned storage (`cocurdex.sqlite`), not as an implicit dual-write Markdown tree in your repository.

## Why app-owned

| Capability | Why SQLite helps |
| --- | --- |
| Stable ids | Titles and folders can change without breaking links |
| Transactions | Multi-row updates stay consistent |
| Revisions | Stale writes can be detected |
| Full-text search | Notes and issues share a search index |
| Backlinks / tags | Normalized graphs instead of path scraping |

Markdown remains available for **explicit** import/export later. Until then, treat the CLI and desktop UI as the only supported writers.

## Notes

Notes support:

- Hierarchical **folders** and note pages (including **New subpage**)  
- A **note title** field separate from the body  
- Markdown bodies, edited as blocks  
- **Tags**  
- **Backlinks** between notes  
- Optional association with a **workspace**  

The notes sidebar groups **Personal** notes and per-workspace sections. Drag a note, or use **Move to**, to reparent it. Double-click a title, or choose **Rename**, to edit it in place — the same control the [Decks](/docs/decks/) list uses.

### Desktop editor

The title sits above the body. **Enter** or **Down** from the title moves the caret into the body.

The body placeholder is **Start writing, or press "/" for commands…**. `/` opens **Insert block**:

| Block | Inserts |
| --- | --- |
| Text / Heading 1–3 | Paragraph or heading |
| Bulleted / Numbered / To-do list | Lists, including checkboxes |
| Quote / Code block / Divider | Common Markdown blocks |
| **Table** | An editable table |

A code block has a **Code language** picker and is highlighted. Paste or drop a PNG, JPEG, GIF, or WebP image (up to 10 MB) into the body to embed it. The same paste and drop works in an issue description.

Tables have click/drag handles on the edge (**Click to add, drag to add more**). Row and column menus cover insert, delete, **Duplicate**, **Clear contents**, alignment (left / center / right), **Sort A → Z** / **Sort Z → A**, and **Delete table**. If the last block in a note is a table, clicking the empty space below it inserts a new empty line so you can keep writing.

Saves show as **Saving…** / **Saved**. The editor also shows when the note was **Created** and **Edited**. Prefer stable titles and links so agents and humans can find the same record later.

**Linked** on a note (and on an issue) lists sessions, notes, issues, and decks tied to that record. **Link an item** searches those four kinds. Remove a link from the same list. The CLI uses the same links:

```bash
cocurdex link list <ref>
cocurdex link add <ref> <ref>
cocurdex link remove <ref> <ref>
```

A ref is `<kind>:<id>` or `cocurdex://<kind>/<id>`, with kind `session`, `note`, `issue`, or `deck`. An issue also accepts its identifier, such as `issue:ACME-12`.

```bash
cocurdex image import <path.png|jpg|gif|webp> [--name <alt text>]
cocurdex image locate <cocurdex://image/...>
```

`image import` prints Markdown you can put in a note or issue. `image locate` prints the local file for an embedded image.

Reading a PDF in the [PDF reader](/docs/desktop/#pdf-reader)? Select text and choose **Add to Note** to quote it into a note.

### CLI

```bash
cocurdex note list
cocurdex note create --title "Architecture notes" --body "## Context\n..."
cocurdex note show <id>
cocurdex note update <id> --body "..."
cocurdex note move <id> --parent <note-id>
cocurdex note move <id> --root
cocurdex note backlinks <id>
cocurdex note tags
cocurdex note delete <id>
```

`--body -` reads Markdown from stdin; `--body-file <path>` reads it from a file.

Create a folder:

```bash
cocurdex note create --title "PRDs" --folder
```

## Issues

Issues are the product’s **todo / ticket / board card** model. Language differs; the storage is one pool:

| You say | Same model |
| --- | --- |
| issue | issue |
| todo | issue |
| ticket | issue |

### Statuses

A status belongs to a **category**. The category decides which scope shows it, and whether its issues count as finished.

| Category | Meaning |
| --- | --- |
| `backlog` | Backlog |
| `unstarted` | Unstarted |
| `started` | Started — in progress |
| `completed` | Completed — finished |
| `canceled` | Canceled — finished |

A new database starts with these statuses:

| Id | Title | Category |
| --- | --- | --- |
| `backlog` | Backlog | `backlog` |
| `todo` | Todo | `unstarted` |
| `doing` | In Progress | `started` |
| `review` | In Review | `started` |
| `done` | Done | `completed` |
| `canceled` | Canceled | `canceled` |

**Manage statuses** (from a column menu or **View display**) adds, renames, and reorders statuses inside a category. Deleting a status moves its issues to another status in the same category, or to the first status when that category has no other. Statuses are shared by every view.

### Default priority values

| Id | Title |
| --- | --- |
| `urgent` | Urgent |
| `high` | High |
| `medium` | Medium |
| `low` | Low |
| `none` | No priority |

### Scopes and saved views

The issues header is three scopes: **All issues**, **Active**, and **Backlog**. **Active** keeps statuses in the unstarted and started categories. **Backlog** keeps the backlog category. Each scope also limits the board's columns to those categories, so a column that can never match stays off the board.

The sidebar lists **Views** you have saved. It starts empty: **Filter issues, then save them as a view.** **Save as view** stores the current scope and filters. Renaming or deleting a view does not delete the issues. Selecting a saved view clears the scope tabs. The CLI's default view id is still **`project`** unless you pass `--view`.

**View display** applies only to that view:

| Control | Options |
| --- | --- |
| **Layout** | **Board** or **List** |
| **Grouping** | **Status**, **Priority**, **Label**, **Parent issue**, or **Workspace** |
| **Display properties** | Which fields a card or row shows: ID, status, priority, labels, workspace, parent, description, created, updated |
| **Show empty groups** | When off, empty columns fold into **Hidden columns**, which still accepts a drop |

Drag a card to update the grouped field. Under **Label**, an issue appears once per label, and dragging it changes only the label it came from. Groups with no value are **No label**, **No parent**, and **No workspace**.

**Filter view** narrows by status, workspace, label, parent (**Top-level only**), and **Created** or **Updated** within the past 1, 7, or 30 days. Each active filter is a chip you can remove. **Hide completed and canceled** is still available.

### Issue page

Open an issue and it fills the issues panel (the board stays underneath, so going back keeps your place). The header is a breadcrumb back to the view, the identifier, and the issue's place in the current list. **Previous issue** and **Next issue** step through that list; `J` and `K` do the same.

The title saves when you leave the field or press **Enter**. The description saves shortly after you stop typing, and again when you leave the page. Status, priority, labels, workspace, and parent save as soon as you change them. A missing issue says **This issue no longer exists.**

The page also has **labels**, **parent** / **sub-issues**, **Issue relations** (blocks / related / duplicate), **Linked** items, linked **Agent sessions**, comments, and an **Activity** feed.

List views and create/move operations go through the daemon (desktop UI or CLI) — do not invent issue ids by hand.

```bash
cocurdex issue views
cocurdex issue view update <id> [--title <title>] [--group-by status|priority|label|workspace|parent] [--layout board|list] [--show-empty true|false] [--properties identifier,status,priority]
cocurdex issue list
cocurdex issue list --status doing [--label <name>] [--parent <id>] [--open]
cocurdex issue create --title "Wire download artifacts" --status backlog --priority high [--body <markdown>|--body-file <path>] [--labels <ids>] [--parent <id>]
cocurdex issue update <id> [--title <title>] [--body <markdown>|--body-file <path>] [--status <column>] [--priority <id>]
cocurdex issue move <id> doing
cocurdex issue move <id> <label> --from <label>
cocurdex issue show <id> [--detail]
cocurdex issue comment <id> --body "Shipped on main"
cocurdex issue relate <id> blocks|related|duplicate <id>
cocurdex issue unrelate <id> blocks|related|duplicate <id>
cocurdex issue labels
cocurdex issue label create --name "release" [--color <color>]
cocurdex issue label update <id|name> [--name <name>] [--color <color>]
cocurdex issue label delete <id|name>
cocurdex issue statuses
cocurdex issue status create --name "Waiting" --category unstarted [--color <color>]
cocurdex issue status update <id|name> [--name <name>] [--category <category>] [--color <color>]
cocurdex issue status move <id|name> --position <n>
cocurdex issue status delete <id|name>
cocurdex issue delete <id>
```

`create`, `update`, and `comment` take the body the same way notes do: `--body -` reads stdin, and `--body-file <path>` reads a file. An unknown flag is rejected and the issue is left unchanged.

`--from` is for a label move: it names the label the card was under, and only that label changes. Status categories are `backlog`, `unstarted`, `started`, `completed`, and `canceled`. `--properties` accepts `identifier`, `status`, `priority`, `labels`, `workspace`, `parent`, `description`, `created`, and `updated`.

## Search

```bash
cocurdex search "download" 
cocurdex search "auth" --kind note
cocurdex search "release" --kind issue --workspace <workspace-id>
```

## Working with agents

Give an agent an issue or note directly from the composer: **+ → Issue** or **+ → Note** attaches it as a pill, and the agent receives the full title and body in its prompt. Clicking the pill in the transcript opens the record.

Product skills (`/cocurdex-note`, `/cocurdex-issue`, …) call the same CLI surface so agents do not open SQLite. See [Skills](/docs/skills/).

Recommended loop for product work:

```text
/cocurdex-note (PRD or spec)  →  /cocurdex-issue  →  /cocurdex-ship
```

PRDs and specs are ordinary notes, stored as **private notes by default**. Publishing into a repository requires an explicit user request — never assume “open workspace” means “write product docs into the repo.”

## On the phone

The iOS and Android app reads and, with **Interact**, edits notes and issues for the computer named in the toolbar. Pairing still needs **Read** to see them. There is no board, no inbox, and no **Activity** or comments on the phone. The phone also has no way to hand a note or issue to an agent. Attach one from the desktop composer with **+ → Note** or **+ → Issue**. Setup for the app is on [Devices and local web](/docs/devices-and-web/#native-app).

### Issues tab

**Issues** groups cards by status, started categories first, then unstarted, backlog, completed, and canceled. Empty statuses are left out. On the default set that puts **In Progress** and **In Review** above **Todo**, **Backlog**, **Done**, and **Canceled**. The header is the status name and a count, such as **In Progress 2**. **Filter** narrows the list. **Search issues** matches a title or an identifier. Pull down to refresh.

**New Issue** is on the toolbar when this phone has **Interact**. The sheet asks for a title and an optional description.

Nothing tracked yet shows **No Issues** — **Issues you track on** that computer **appear here.** A search with no matches shows **No issues match** the query. A filter with no matches shows **No issues match these filters**. If the list cannot load, the screen is **Couldn’t load issues from** that computer, and **Try Again**.

Each row shows a status mark, the title, then the identifier and labels. Long-press a row for **Move**, which changes its status. Open it and the header is the identifier. The page shows the title, the description as Markdown when it has one, then **Status**, **Priority**, **Labels** (**None** when there are no labels), and **Workspace**. With **Interact**, those rows open a picker and save immediately, and **Edit** changes the title and description. When sessions are linked, **Agent Sessions** lists them; tap one to open it. A session with no title reads **Untitled session**. When there are sub-issues, the header is the done count over the total, such as **Sub-issues 1/3**, and the page lists those children. A deleted issue shows **This issue was deleted on the computer.**

### Notes tab

**Notes** groups notes by workspace as an indented tree. A note with no workspace sits under **No Workspace**. Folders stay in the tree; open a note to read it. **Search notes** matches titles. Inside each workspace the matches are a flat list, newest first. Pull down to refresh.

**New Note** is on the toolbar when this phone has **Interact**.

An empty computer shows **No Notes** — **Notes you write on** that computer **appear here.** A search with no matches shows **No notes match** the query. If the list cannot load, the screen is **Couldn’t load notes from** that computer, and **Try Again**.

The note page shows the title, the workspace, how long ago it changed, and the Markdown body — the same rendering as a session transcript. **Edit** (with **Interact**) opens the body: the placeholder is **Write something, or type / to insert headings, lists, and to-dos**. The format bar covers **Bold**, lists, and **Text Style** (body and headings). **Insert** adds a quote, code block, divider, list, checklist, or table. Saves show **Saving…** / **Saved**, or **Not saved**. **Done Editing** leaves the editor. **Note Properties** can set the **Parent Note**. A deleted note shows **This note was deleted on the computer.**

## What not to do

- Do not treat paths under the project as issue identity  
- Do not hand-edit `cocurdex.sqlite`  
- Do not invent issue or note ids in scripts — create via CLI and keep returned ids  
- Do not dual-write Markdown copies “for safety” unless you own an explicit export workflow
