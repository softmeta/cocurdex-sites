The **`cocurdex` CLI** is the supported command-line boundary for app-owned product data and daemon operations. External tools and agents should use the CLI rather than reading private database files.

Most data and session commands require the **desktop daemon**. Opening the desktop app starts it. The CLI packaged with the app starts the daemon itself when nothing is listening, so commands keep working with the desktop window closed. If that launcher cannot start one, open the desktop app and retry.

**Keep running in the background** (**Settings → General → Daemon**) is off until you turn it on. On, the daemon keeps serving the CLI and paired devices after you quit, and it starts when you log in. Off, quitting the desktop app stops the daemon it owns. See [Daemon and workspaces](#daemon-and-workspaces).

## Install

When the CLI is packaged with the desktop app, install the launcher from **Settings → General → Shell command** so `cocurdex` is on your `PATH`.

```bash
cocurdex --version
cocurdex --help
```

In monorepo development, use the workspace CLI package (`apps/cli`).

### Finding the desktop binary

Open flows need the Cocurdex / Electron binary. Resolution order includes:

1. `COCURDEX_ELECTRON` environment variable  
2. Running under Electron / packaged app  
3. Development `node_modules/electron` under the monorepo  
4. Common macOS install paths (`/Applications/Cocurdex.app/...`)

If resolution fails, open the desktop app once and install the CLI launcher, or set `COCURDEX_ELECTRON`.

Platform notes:

- **Linux AppImage** — the launcher runs a stable copy of the CLI bundle, so it keeps working after the AppImage mount goes away.
- **Windows** — the launcher is a shim on your user `PATH`; uninstalling Cocurdex removes the shim and its `PATH` entry.

## Notes

```bash
cocurdex note list [--json]
cocurdex note show <id> [--json]
cocurdex note create --title <title> [--body <markdown>] [--parent <id>] [--workspace <id>] [--folder] [--json]
cocurdex note update <id> [--title <title>] [--body <markdown>] [--json]
cocurdex note move <id> --parent <note-id> | --root [--json]
cocurdex note delete <id> [--json]
cocurdex note backlinks <id> [--json]
cocurdex note tags [note-id] [--json]
```

| Flag | Meaning |
| --- | --- |
| `--title` | Required on create |
| `--body` | Markdown body (`-` reads stdin). `--body-file <path>` reads a file |
| `--root` | On `move`, lift the note to the sidebar root |
| `--folder` | Create a folder node instead of a note |
| `--parent` | Parent note/folder id |
| `--workspace` | Optional workspace association |

Updates use optimistic concurrency (revision) under the hood — always prefer CLI/desktop over editing SQLite.

## Issues

Default view id is `project` unless you pass `--view`.

```bash
cocurdex issue list [--status <column>] [--label <name>] [--parent <id>] [--open] [--view <id>] [--json]
cocurdex issue show <id> [--detail] [--view <id>] [--json]
cocurdex issue create --title <title> [--status <column>] [--priority <id>] [--body <markdown>|--body-file <path>] [--workspace <id>] [--parent <id>] [--labels <ids>] [--view <id>] [--json]
cocurdex issue update <id> [--title <title>] [--body <markdown>|--body-file <path>] [--status <column>] [--priority <id>] [--workspace <id>|none] [--parent <id>|none] [--labels <ids>] [--view <id>] [--json]
cocurdex issue move <id> <column> [--view <id>] [--json]
cocurdex issue comment <id> --body <markdown>|--body-file <path> [--json]
cocurdex issue relate <id> blocks|related|duplicate <id> [--json]
cocurdex issue unrelate <id> blocks|related|duplicate <id> [--json]
cocurdex issue labels [--json]
cocurdex issue label create --name <name> [--color <color>] [--json]
cocurdex issue label delete <id|name> [--json]
cocurdex issue delete <id> [--view <id>] [--json]
cocurdex issue views [--json]
```

Default **status** values: `backlog` (Backlog), `todo` (Todo), `doing` (In Progress), `review` (In Review), `done` (Done), `canceled` (Canceled). Each status has a category: `backlog`, `unstarted`, `started`, `completed`, or `canceled`.  
Default **priority** columns: `urgent`, `high`, `medium`, `low`, `none`.

Statuses, labels, and saved views:

```bash
cocurdex issue statuses [--json]
cocurdex issue status create --name <name> --category backlog|unstarted|started|completed|canceled [--color <color>]
cocurdex issue status update <id|name> [--name <name>] [--category <category>] [--color <color>]
cocurdex issue status move <id|name> --position <n>
cocurdex issue status delete <id|name>
cocurdex issue label update <id|name> [--name <name>] [--color <color>]
cocurdex issue view update <id> [--title <title>] [--group-by status|priority|label|workspace|parent] [--layout board|list] [--show-empty true|false] [--properties <a,b>]
cocurdex issue move <id> <column> [--from <column>]
```

`create`, `update`, and `comment` take the body the same way notes do: `--body -` reads stdin, and `--body-file <path>` reads a file. An unknown flag is rejected and the issue is left unchanged. The error is `Unknown flag --<name> for "issue <action>". Accepted flags: ...`.

`--from` names the label a card was under, and only that label changes. `--properties` accepts `identifier`, `status`, `priority`, `labels`, `workspace`, `parent`, `description`, `created`, and `updated`. See [Notes and issues](/docs/notes-and-issues/#issues).

Examples:

```bash
cocurdex issue create --title "Fix download page" --status backlog --priority high
cocurdex issue move <id> doing
cocurdex issue list --status doing
```

## Decks

Slide decks are app-owned records: Markdown in, a 16:9 deck out, with a checker for overflow, empty slides, and unknown slots. Layouts, themes, presenting, and the `/cocurdex-deck` skill: [Slide decks](/docs/decks/).

```bash
cocurdex deck list [--json]
cocurdex deck show <id> [--json]
cocurdex deck create [--title <title>] [--markdown-file <path|-> | --content-file <path|->] [--workspace <id>] [--json]
cocurdex deck update <id> [--title <title>] [--markdown-file <path|-> | --content-file <path|->] [--expected-revision <n>] [--json]
cocurdex deck edit <id> --ops-file <path|-> [--expected-revision <n>] [--json]
cocurdex deck image <id> --slide <slideId> --file <path.png|path.jpg> [--alt <text>] [--replace <elementId>] [--expected-revision <n>] [--json]
cocurdex deck check <id> [--json]
cocurdex deck export <id> --output <path.pptx|path.pdf> [--format pptx|pdf] [--json]
cocurdex deck import <file.pptx> [--title <title>] [--workspace <id>] [--json]
cocurdex deck read <file.pptx> [--json]
cocurdex deck delete <id> [--json]
```

| Flag | Meaning |
| --- | --- |
| `--markdown-file` / `--content-file` | Markdown source, or structured deck JSON. `-` reads stdin. Mutually exclusive and optional. Omit both to create a deck with no slides, or to leave slides unchanged on update |
| `--ops-file` | JSON array of edit ops, or `{ "ops": [ ... ] }`. Applied in order; a failure saves nothing |
| `--expected-revision` | Revision from `deck show`. A stale write fails with `Deck was modified` |
| `--output` / `--format` | Export path. Format is `pptx` or `pdf`, or the output extension |
| `--workspace` | Optional workspace id on create or import |
| `--slide` / `--file` / `--alt` / `--replace` | Add a PNG or JPEG (up to 20 MB), or swap one and keep its frame |

`deck list` prints id, title, slide count, revision, and updated time. `deck show` includes checker issues. `deck read` prints the PowerPoint file as Markdown and does not create a deck. `deck import` creates a deck and leaves the file untouched. A line that is only `---` splits slides; a paragraph starting with `Notes:` or `备注：` starts speaker notes.

## Assistants

Personal assistants, delegated work, applications, routines, and the inbox. Full model: [Assistants](/docs/assistants/). A `<persona>` or `<routine>` is the id, a unique id prefix, or the name.

```bash
cocurdex persona list [--json]
cocurdex persona show <persona> [--json]
cocurdex persona create --name <name> [--provider <id> --model <id>] [--description <text>] [--instructions <text>|--instructions-file <path>] [--soul <text>|--soul-file <path>] [--json]
cocurdex persona update <persona> [--name <name>] [--provider <id> --model <id>] [--description <text>] [--instructions <text>|--instructions-file <path>] [--soul <text>|--soul-file <path>] [--pin|--unpin] [--mute|--unmute] [--json]
cocurdex persona duplicate <persona> --name <name> [--json]
cocurdex persona delete <persona>
cocurdex persona send <persona> <message> [--wait] [--timeout <seconds>] [--json]
cocurdex persona thread <persona> [--limit <n>] [--json]
cocurdex persona work catalog [--json]
cocurdex persona work list <persona> [--json]
cocurdex persona work start <persona> --workspace <id|name> --prompt <text>|--prompt-file <path> [--title <title>] [--role <role>|--team <template>] [--worktree] [--json]
cocurdex persona work send <persona> <session-id> <message> [--json]
cocurdex persona work stop <persona> <session-id> [--json]
cocurdex routine list [--persona <persona>] [--json]
cocurdex routine show <routine> [--json]
cocurdex routine create --persona <persona> --name <name> (--prompt <text>|--prompt-file <path>) (--every <minutes>|--at <HH:MM> [--days <mon,wed|weekdays|weekends>]) [--tz <zone>] [--access read-and-draft|full] [--deliver inbox|push|silent] [--json]
cocurdex routine update <routine> [--name <name>] [--prompt <text>|--prompt-file <path>] [--every <minutes>|--at <HH:MM> [--days <days>]] [--tz <zone>] [--access read-and-draft|full] [--deliver inbox|push|silent] [--json]
cocurdex routine pause|resume <routine> [--json]
cocurdex routine run <routine> [--wait] [--timeout <seconds>] [--json]
cocurdex routine runs [<routine>] [--limit <n>] [--json]
cocurdex routine delete <routine>
cocurdex inbox [list] [--json]
cocurdex inbox read <item-id> [--json]
cocurdex inbox brief [--tz <zone>] [--json]
cocurdex inbox brief post [--tz <zone>] [--locale en-US|zh-CN] [--json]
```

Personal assistants always run on Pi. There is no `--agent` flag on `persona create` or `persona update`. `--provider` and `--model` go together. `persona send --wait` prints the reply (default timeout 600 seconds). `persona delete` removes that assistant, including the default: the next one in the list becomes the default, and an empty list stays empty. `routine create` needs `--prompt` or `--prompt-file`, and either `--every` (at least 5) or `--at`. `--access` is `read-and-draft` (default) or `full`. `inbox read` marks the item's thread visited. `inbox brief` prints `Nothing to brief today.` when there is nothing to report. `inbox brief post` writes today's brief into the default assistant's home thread. `--locale` is `en-US` or `zh-CN`; omit it to reuse the last locale used for a post. Nothing new to post prints `Nothing new to post.`

`persona work` hands repository work to a work session. `catalog` lists workspaces, saved agent roles, and team templates. `list` prints `sessionId`, `title`, `workspaceName`, `agentType`, and `state`. `--workspace` is an id or a name. More than one workspace with that name fails with `Several workspaces are named "<name>"; pass its id.` `--role` and `--team` are alternatives (`Pass either an agent role or a team template, not both.`). `--prompt-file` reads the task from a file. `--worktree` uses a new git worktree. `send` and `stop` accept only a session this assistant delegated (`No work session you delegated has this id.`). See [Delegated work](/docs/assistants/#delegated-work).

## Daemon and workspaces

```bash
cocurdex daemon status
cocurdex daemon background on|off|status [--json]
cocurdex workspace list
```

`daemon background` is **Settings → General → Daemon → Keep running in the background**.

- `on` keeps the daemon running after you quit Cocurdex, and registers it to start at login: a LaunchAgent on macOS, a Run key on Windows, or an XDG autostart entry on Linux.
- `off` removes that login item. Quitting the desktop app then stops the daemon it owns.
- `status` prints one line. After a successful change, `on` and `off` print that line too:
  - Background mode is off: the daemon stops when Cocurdex quits
  - Background mode is on: the daemon keeps running after Cocurdex quits and starts at login
  - Background mode is on, but the login item is missing; run `cocurdex daemon background on` to restore it
  - Background mode is not available for this daemon (source build). **Settings → General → Daemon** then hides the switch, and `on` or `off` fails with `Background mode is not available for this daemon`
- `--json` prints `enabled`, `available`, and `registered`.

Only this computer can change the setting. A paired device is refused with `Only this computer can change background mode`. `daemon status` and `daemon health` are also listed under [Diagnostics](#diagnostics).

## Devices and local web

Print the local web client URL. The daemon must be running. **Keep running in the background** keeps it up after you quit the desktop app, and the packaged CLI starts it when it is down:

```bash
cocurdex web [--json]
```

Pair another device with the host daemon. Full model: [Devices and local web](/docs/devices-and-web/).

```bash
cocurdex host status [--json]
cocurdex host remote enable [--port <port>] [--keep-awake on|off] | disable [--json]
cocurdex host pair --label <name> [--scopes read,interact,approvals] [--ttl <minutes>] [--json]
cocurdex host pairings [--json]
cocurdex host pairing cancel <pairing-id>
cocurdex host devices [--json]
cocurdex host approve <device-id> --code <safety code>
cocurdex host revoke <device-id>
cocurdex host scopes <device-id> --scopes <list>
cocurdex host traffic [--reset] [--json]
cocurdex host relay set [official|<url>] [--relay-only on|off] [--credential <file>]
cocurdex host relay off
cocurdex host push set <url> | off
cocurdex host push status [--json]
cocurdex host audit [--limit <n>] [--json]
```

`--scopes` is a comma-separated list of `read`, `interact`, `execute`, `files.read`, `files.write`, `git.destructive`, `approvals`, `credentials`, and `devices`. Default pairing scopes are `read,interact,approvals`. `host.admin` cannot be granted. `host approve` types the safety code shown on the device that is waiting.

## Worktrees

Managed git worktrees give sessions an isolated checkout of a workspace repository.

```bash
cocurdex worktree list [--json]
cocurdex worktree settings [--root <path>] [--fetch|--no-fetch] [--json]
cocurdex worktree create --workspace <id|path> --branch <name> [--start-point <rev>] [--json]
cocurdex worktree remove --workspace <id|path> --path <worktree-path> [--json]
```

`worktree settings` with no flags prints the current settings; pass `--root` and/or `--fetch`/`--no-fetch` to update them. `--root` sets the directory where Cocurdex creates managed worktrees (empty clears it back to the default location); `--fetch` controls whether the repository is fetched before creating a worktree.

## Sessions

```bash
cocurdex session list
cocurdex session create --workspace <id|path> [--agent <agent>] [--provider <provider> --model <model>] [--permission <mode>] [--role <role-id>] [--title <title>]
cocurdex session runtime <session-id> [--json]
cocurdex session configure <session-id> [--provider <id> --model <id>] [--effort <level|default>] [--thinking <level|off|default>] [--fast on|off|default] [--service-tier <tier|default>] [--opencode-agent <name|default>] [--opencode-variant <name|default>] [--json]
cocurdex session tui [session-id]
cocurdex session tui --workspace <id|path> [--agent <agent>] [--provider <provider> --model <model>] [--permission <mode>] [--title <title>]
cocurdex session send <session-id> <prompt>
cocurdex session tree <session-id> [--depth <n>] [--json]
cocurdex session fork <session-id> [--through <message-id>] [--title <title>] [--json]
cocurdex session switch-agent <session-id> <agent> [--json]
cocurdex session handoffs <session-id> [--json]
cocurdex session peers <session-id>
cocurdex session send-peer <from-session-id> <to-session-id> <message>
cocurdex session peer-inbound <session-id> deliver|refuse
cocurdex session stop <session-id>
```

| Flag | Required for | Meaning |
| --- | --- | --- |
| `--workspace` | create, and tui when creating | Workspace id or filesystem path |
| `--agent` | optional | Agent id: `claude-agent`, `codex`, `opencode`, `pi`, or an installed ACP Registry agent such as `acp:cursor`, `acp:devin`, `acp:grok-build` |
| `--provider` | optional, with `--model` | Provider config id from `provider list` |
| `--model` | optional, with `--provider` | Model id from `provider models` |
| `--permission` | optional | Permission mode id for that agent. Ids: [Agents](/docs/agents/#permission-modes) |
| `--title` | optional | Session title. Omit it and the title is the agent's name |
| `--role` | optional | Saved [agent role](/docs/agents/#agent-roles). It supplies the agent, model, and permissions |

`session runtime` prints the model and runtime axes the session is using. `session configure` changes them on that session. `default` on a flag clears that axis back to the agent's own default. `--fast` is `on`, `off`, or `default`.

The daemon fills in whatever you leave out. Omit `--agent` and the session uses the agent from the workspace's most recently updated session. If that agent is not available, or the workspace has no session yet, it uses the first agent available on this computer. Omit `--permission` and it uses the mode from the most recently updated session of that agent in the workspace, when the model still allows it; otherwise the first mode the model allows. An agent with no permission modes, such as Pi, leaves the mode unset. Omit `--provider` and `--model` together and the model is the agent's default, then the model that agent last used in the workspace, then the first compatible model. If the agent has no compatible model, the session is still created and the model is left unset. A command that still passes `--agent`, `--provider`, and `--model` keeps working.

`--provider` and `--model` have to be given together. One without the other fails with `--provider and --model must be given together`. An agent that is not available on this computer fails with `<agent> is not available on this machine`. When no agent is available and you omit `--agent`, the message is `No agent is available on this machine`. A model that agent cannot use fails with `<provider>/<model> is not available for <agent>`. A mode that agent does not offer fails with `<mode> is not a permission mode of <agent>`.

`session tui` without flags attaches to the latest non-archived session. Passing `--workspace`, `--agent`, `--provider`, or `--model` creates a session through the same defaults as `session create` — that create still requires `--workspace` — then attaches. `--permission` and `--title` apply when it creates. It does not support `--json`.

`session tree` prints the [execution tree](/docs/desktop/#execution-tree). `fork` starts a new session from this one (`--through` cuts off after that message). `switch-agent` changes the runtime on an idle session. `handoffs` lists context transfers after a fork or agent switch. See [Fork and switch agent](/docs/desktop/#fork-and-switch-agent).

`peers` lists the sessions a session can message; `send-peer` delivers a message as a new turn (or queues it after the current one); `peer-inbound refuse` stops a session from accepting peer messages. See [Peer messaging](/docs/teams/#peer-messaging).

Agent ids and permissions: [Agents](/docs/agents/).

## Script runs

Approved JavaScript fan-outs to subagents. Full model: [Script runs](/docs/teams/#script-runs).

```bash
cocurdex script-run list [--session <requester-session-id>] [--workspace <workspace-id>] [--json]
cocurdex script-run get --run <run-id> [--json]
cocurdex script-run create --session <requester-session-id> --name <name> --file <script.js>
cocurdex script-run start --run <run-id> [--max-agents <n>]
cocurdex script-run cancel --run <run-id>
```

`create` makes a `draft` run owned by the requester session; `start` approves and runs it with an agent limit (a positive integer). The result is delivered back to the requester session.

| `add` | Needs `--base-url` or a `--template` from `provider templates` |
| `login` | Defaults to `--method oauth`; uses a terminal UI when stdin and stdout are TTYs, plain text with `--no-tui` |
| `models --refresh` | Fetches the catalog from the provider instead of the stored list |
| `model add --api` | One of `openai-completions`, `openai-responses`, `openai-codex-responses`, `anthropic-messages`, `google-generative-ai`, `mistral-conversations` |
| `default` | Without flags, lists the default provider and model per agent; with `--agent --provider --model`, sets one |
| `model set` | Edits one model's parameters. A built-in catalog model keeps the fields you did not change. `--context` and `--output` take a token count or `none` |
| `model reset` | Drops those edits and restores the catalog values. The model row in Settings shows **Edited** until you reset it |

```bash
cocurdex provider model set <id> <model-id> [--enable|--disable] [--api <api>] [--context <tokens>|none] [--output <tokens>|none] [--capabilities <a,b>] [--reasoning on|off]
cocurdex provider model reset <id> <model-id>
```

## Agents

Sign-in and updates for ACP Registry agents. The desktop screen is [Agent CLIs](/docs/providers-and-settings/#agent-clis).

```bash
cocurdex agent auth <agent> [--json]
cocurdex agent login <agent> [--method <method-id>]
cocurdex agent login cancel <agent>
cocurdex agent logout <agent>
cocurdex agent updates [--refresh] [--json]
cocurdex agent update <agent> [--json]
```

`agent auth` lists login methods. A star marks the one in use. `agent updates` lists installed registry agents that have a newer version. `agent update` installs that version.

## MCP servers

Servers Cocurdex gives to agents. The desktop screen is [MCP servers](/docs/providers-and-settings/#mcp-servers), under **Settings → Connections**.

```bash
cocurdex mcp list [--workspace <id|path>] [--json]
cocurdex mcp show [<name>]
cocurdex mcp add <name> [--env KEY=VALUE]... [--cwd <dir>] [--description <text>] [--disabled] [--agent <id>]... -- <command> [args...]
cocurdex mcp add <name> --url <url> [--header KEY=VALUE]... [--bearer-token-env-var <NAME>] [--description <text>] [--disabled] [--agent <id>]...
cocurdex mcp remove <name>
cocurdex mcp enable|disable <name>
cocurdex mcp agents <name> [<agent>...|--none] [--json]
cocurdex mcp test <name> [--workspace <id|path>] [--json]
cocurdex mcp login <name> [--workspace <id|path>]
cocurdex mcp logout <name> [--workspace <id|path>]
cocurdex mcp import <file|-> [--overwrite]
cocurdex mcp import --from claude|claude-project|codex|codex-project|cursor|opencode|opencode-project|antigravity [--name <name>]... [--overwrite] [--workspace <id|path>]
```

`--agent` may be repeated. `agents <name> --none` clears the agent list. `import --from` reads servers that agent already has on this computer; repeat `--name` to import only those servers. A Notion, Linear, or GitHub connection managed in **Applications** is not assigned to agents here. `mcp agents` on it fails with `Manage assistant access with cocurdex apps update.`

## Applications

Notion, Linear, and GitHub accounts for assistants. The desktop screen is [Applications](/docs/assistants/#applications). These commands print JSON. `login-cancel` only stops that authorization and prints nothing.

```bash
cocurdex apps catalog|list [--json]
cocurdex apps add <notion|linear|github> --name <name> [--assistants <id,id>|--all-assistants true|false] [--delegated true|false] [--work-sessions true|false] [--json]
cocurdex apps update --stdin [--json]
cocurdex apps check|tools|logout|remove <connection-id> [--json]
cocurdex apps login <connection-id> [--json]
cocurdex apps login-wait|login-cancel <connection-id> --login <id> [--json]
cocurdex apps login-return <connection-id> --login <id> --stdin [--json]
cocurdex apps read|call <connection-id> --tool <name> --stdin [--json]
```

| Command | Does |
| --- | --- |
| `catalog` | Prints Notion, Linear, and GitHub. Does not need a running daemon |
| `add` | `--name` is required. Omit `--all-assistants` and `--assistants` and the new connection stays open to all assistants, including ones created later. `--assistants` without `--all-assistants` turns that off and grants those assistant ids, comma-separated. `--all-assistants`, `--delegated`, and `--work-sessions` take `true` or `false`. A flag with no value means `true`. Any other value fails with `--<flag> takes true or false`. Omit `--delegated` or `--work-sessions` and that switch stays on (**Allow delegated work** and **Available in work mode**). An unknown id fails with `Choose notion, linear, or github` |
| `update` | Reads one JSON object from stdin. Fields: `id`, `revision`, `displayName`, `allPersonas`, `personaIds`, `allowDelegatedWork`, `allowWorkSessions`, `enabled`. Omit `allPersonas` or `allowWorkSessions` and the connection keeps that setting. Putting that JSON in command arguments fails with `Pass the update JSON through --stdin; never put credentials in command arguments.` A stale `revision` fails with `Application changed. Reload before saving.` |
| `check` / `tools` / `logout` / `remove` | One connection id. `remove` prints `{ "removed": true }` |
| `login` | Starts authorization and prints that login, including its id. GitHub uses a `gh` sign-in when one is available, or a device code |
| `login-wait` / `login-cancel` | `--login` is that login id |
| `login-return` | The complete return URL is the text on stdin, not an argument. With no stdin it fails with `Pass the complete return URL through --stdin`. A GitHub device login fails with `GitHub authorization finishes in the browser` |
| `read` / `call` | `--tool` is the tool name. Arguments are one JSON object on stdin. `read` is limited to tools the provider declares read-only. The id is the connection id. In a session, `applications_tools`, `applications_read`, and `applications_call` also accept `notion`, `linear`, or `github` when that session is allowed exactly one connection for it. See [Applications](/docs/assistants/#applications) |

## Diagnostics

```bash
cocurdex daemon status [--json]
cocurdex daemon health [--json]
cocurdex daemon background on|off|status [--json]
cocurdex diagnostics export [--json]
cocurdex diagnostics level debug|info [--json]
```

`daemon health` prints the process, memory, active work, and where logs are. `daemon background` turns **Keep running in the background** on or off, or prints its status. See [Daemon and workspaces](#daemon-and-workspaces). `diagnostics export` writes the same sanitized bundle as **Settings → Diagnostics**. `diagnostics level` is **Verbose diagnostics**: `debug` records more, `info` is the normal level. See [Diagnostics](/docs/providers-and-settings/#diagnostics).

## Agent roles

Saved agent presets (agent + provider/model + permission + reasoning axes, avatar, description) that sessions, teammates, and script-run subagents can use. Manage them in the desktop UI; list them from the CLI:

```bash
cocurdex role list [--json]
```

## What the CLI is not

- A second source of truth — the desktop daemon still owns the local database  
- A full replacement for the multi-pane desktop workspace  
- A cloud team admin tool (that will be a separate console + API)  
- A license to open `cocurdex.sqlite` or private schema paths  

## Safety

Do not point scripts at `cocurdex.sqlite` or private schema paths. Those are implementation details and can change without a compatibility promise during pre-release. Prefer `--json` output and stable ids returned by the CLI.
