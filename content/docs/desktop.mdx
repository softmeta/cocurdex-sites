Cocurdex ships as a **native desktop app** (Electron). The goal is a single workspace for multi-agent coding — not a thin browser wrapper around one chat thread.

## Surfaces

Typical peers in the shell:

| Surface | Role |
| --- | --- |
| **Sessions** | Track parallel agent runs and which one needs attention |
| **Chat** | Steer the active agent; one pane among several |
| **Assistants** | Personal assistants, their home threads, overview, connected applications, and today's brief (see [Assistants](/docs/assistants/)). The list can be empty |
| **Terminal** | Integrated PTY for commands and agent-driven shell work |
| **Editor** | Inspect and edit project files without leaving the app |
| **Git** | Diff, stage, and commit workspace changes; review what each agent turn changed |
| **Browser preview** | Tabbed preview of your dev server; Design Mode annotations go straight to chat |
| **PDF reader** | Read PDFs from the file tree or a conversation, with outline, thumbnails, search, bookmarks, and highlights |
| **Worktrees** | Managed git worktrees for isolated session work (**Worktree** checkbox on new sessions; inventory under **Settings → Worktrees**) |
| **Notes / issues** | App-owned product data (see [Notes and issues](/docs/notes-and-issues/)) |
| **Decks** | App-owned slide decks: edit, present, and export (see [Slide decks](/docs/decks/)) |
| **Team panel** | Teammates of the current lead session, their status, and replies (see [Teams](/docs/teams/)) |
| **Script runs** | Proposed scripts awaiting approval and running subagents (see [Script runs](/docs/teams/#script-runs)) |

The right panel can float over chat or, with its pin button, dock beside it so the chat column shrinks instead; the choice is remembered. **Close editor panel** hides it. Each mode has its own switcher. On **Work** the tabs are **Files**, **Git**, **Terminal**, **Issues**, **Notes**, **Browser**, and **Decks**. **More views** holds **Memory** and **Routines**. On **Chat** the tabs are **Notes**, **Memory**, and **Browser**. **More views** holds **Issues**. **Git** and **Terminal** appear only on **Work**, because a chat directory is not a repository. Opening an attachment or a file from **Chat** reveals **Conversation files**: attachments and files opened in this conversation, the same view an assistant uses. The file tree and workspace search appear only on **Work**. **Conversation files** appears as a tab only while that view is active; switch away and the tab is hidden until a file is opened again. Opening an assistant switches this to **Assistant overview**. The assistant's tabs are **Assistant overview**, **Memory**, **Notes**, **Issues**, and **Routines**. **More views** holds **Conversation files**, **Browser**, and **Decks**. **PDF** appears in any mode while a PDF is open. A **More views** item that is the active view also shows beside the other tabs. **Work**, **Chat**, and **Assistants** each remember their own view, so a tab chosen on **Work** stays there. **Chat** defaults to **Notes**. Hover an icon-only button to see its action name. On an assistant thread the name and avatar float over the conversation, and the title bar keeps the panel toggles. On Windows and Linux the window uses themed native window controls in the title bar. See [Assistants](/docs/assistants/#overview).

Chat layout is chosen in **Settings → General → Chat layout** and restored on next launch:

| Layout | Behavior |
| --- | --- |
| **Center column** | Chat is the main column |
| **Floating dock** | Chat floats over the editor |
| **Pinned right rail** | Chat docks beside the editor |

When chat is closed in floating or pinned layout, **Hide chat button when closed** removes the bottom-right button; open chat again with the chat-dock shortcut. HTML generated in replies can preview in the **chat area** or the **sidebar browser**.

Exact layout can change during pre-release; the product model stays multi-pane. No single pane should monopolize the product — chat is a peer, not the whole app.

You can also [open the same host in a browser](/docs/devices-and-web/) on this computer, or pair another device.

## Sidebar

The switcher at the top of the sidebar chooses **Work**, **Chat**, or **Assistants**. Each row in that menu has a one-line description: **Build, fix, and ship in your projects**, **Ask anything, get quick answers**, and **Remembers you and minds your day**. **Open search** is in the title bar, after **Back** and **Forward** (`Primary+P`). The switcher's own row holds that form's action and an icon-only create button: **Add workspace** and **New session** on Work, **New chat** on Chat, and **Today's brief** (when there is one) plus **New assistant** on Assistants. With no assistants yet, the pane invites you to create the first one. See [Assistants](/docs/assistants/).

Rows, section headings, and the assistant roster sit on the same 12px inset as the header icons. The scrollbar draws above the list, including over the sticky **Sessions** heading.

The sidebar footer shows **Proxy status** and **Settings**. **Settings** also opens with `Primary+,`, including while the sidebar is collapsed. On Assistants the footer also shows **Apps**, which opens [Applications](/docs/assistants/#applications), and **Long-term memory**.

## Sessions and attention

You can run **more than one** session without merging transcripts. The shell derives a **primary state** so you can scan who needs you:

| Kind | Examples | What to do |
| --- | --- | --- |
| Needs you | Pending approval, awaiting input, plan ready | Open the session and resolve the permission, question, or plan |
| Busy | Working, connecting, monitoring | Wait or steer if the runtime supports it |
| Result | Completed / unread | Review output, then mark settled by visiting or continuing |
| Idle | Ready | Available for a new prompt |

Underlying session status values include `idle`, `running`, `error`, and `exited`. UI copy stays neutral (“Thinking”, “Using tools”, “Ready for follow-up”) rather than anthropomorphic flourish.

### Session list

On **Work**, the **Group and filter sessions** menu on the **Sessions** heading controls how sessions are listed. Chat threads and assistant home threads are not in this list:

| Control | Options |
| --- | --- |
| **Group by** | Workspace, status, agent, last updated, or no grouping |
| **Sort by** | Recent activity, created time, or title |
| **Filters** | Agent, status, environment (local vs worktree), source, unread |
| **Sessions per group** | Cap how many root sessions show; **Show more** reveals the rest |
| **Properties** | **Last activity**, **Agent**, **Model**, **Role**, **Workspace**, or **Worktree**. A row shows none of these until you choose them, so it has no time by default |
| **Compact mode** | Denser rows. It keeps **Last activity** only when you chose that property, and hides the others |

**Pin** keeps a session at the top of the list. **Archive** hides one session; **Archive sessions** on a group moves matching sessions to **Settings → Archived sessions**, skipping pinned, running, and waiting ones — **Undo** restores them. **Delete** or **Archive** on the session you have open selects the next session in the same form — **Work**, **Chat**, or **Assistants**. When that form has none left, the selection clears. Nested subagent sessions expand and collapse in the tree.

Chat rows do not show a time.

### Execution tree

**Execution tree** on a session's sidebar menu shows runs, tool calls, subagents, and pending approvals for the session. Expand a row to see what it contains; select a tool call to read its output. **Issues only** filters to failed calls and waiting approvals. Some provider-native subagents are not observable.

### Fork and switch agent

**Fork session** in the sidebar starts a new session from the current one. On a user message, **Fork from here** starts the fork through that prompt — useful to try a different path without losing the original. The new title gets a `(fork)` suffix.

While a session is not running, pick a different agent in the composer's agent menu. Each option shows that agent's brand icon beside its name, the same way the agent menu on a new session does. Cocurdex hands conversation context to the new runtime. Claude Agent and Codex can fork onto the provider's own thread; a marker in the transcript can **Show** / **Hide handed-off context**. Pi sidebar **Chat** conversations cannot be forked or switched this way.

## Composer

The composer starts every session and every follow-up:

| Input | Does |
| --- | --- |
| `/` | Pick a skill or an agent-advertised slash command |
| `@` | Mention workspace files as context |
| **+ → Skill / Issue / Note** | Insert a skill, or attach an issue or note as a pill; the agent gets its full content in the prompt |
| Model menu | Agent, provider, model, reasoning effort, permission mode; **Save as role** stores the setup as an [agent role](/docs/agents/#agent-roles). A saved role leads that control: its avatar and name sit with the model |
| **+ → Memory** | Turn [memory](/docs/memory/) on, sync it, or open its settings |
| **Worktree** checkbox (new session) | Run the session in a fresh [managed worktree](#worktrees) |

With no folder open, the work-session placeholder is **Open a folder, then describe the task**. Sending still works: Cocurdex opens the folder picker and keeps what you typed if you cancel.

Follow-ups sent while a turn runs are steered into it when the agent supports steering, or queued until the turn finishes (**Settings → General → Follow-up behavior**). When a turn settles, its tool calls fold behind a label that shows how long the turn worked; expand it to review every step. While a work-mode turn is still running, the thread shows the elapsed time and the activity: **Thinking**, **Using tools**, **Working**, or **Replying**. Every composer has more space below it. On an assistant thread the composer is a single row, without those agent and model controls, and the live label does not include that elapsed time. See [Assistants](/docs/assistants/#home-thread).

**Settings → General → Transcript view** chooses how much of that work is visible: **Concise** (final replies only), **Standard** (folded summaries), or **Verbose** (everything expanded).

In a long transcript, a prompt rail jumps to each user message; **Jump to latest** and **Jump to top** skip the scroll. The context-window meter on a reply shows token usage; when the runtime compacts context, the transcript records that it happened.

Markdown links in replies that point at files open in the editor, including GitHub-style line anchors such as `src/app.ts#L32` or `#L10-L20`. HTML in replies can be previewed or shown as source; Mermaid diagrams offer **Open preview** and **Download SVG**.

## Worktrees

Tick **Worktree** on the new-session composer and Cocurdex creates an isolated checkout when you send: it names the branch `cocurdex/<id>` and places the checkout under the [worktree root](/docs/providers-and-settings/#worktree-environments). Alternatively, pick an existing worktree from the picker (disabled while the checkbox is on).

- The workspace's **setup script** runs in the background. The composer does not block; the first turn waits for setup so its changes are not attributed to the agent, and progress shows as a **Prepare worktree** row. Stop abandons the wait without killing the script; a failed setup is reported once and the next send continues without it.
- Workspace **actions** (for example *Dev server*) appear in the session's **…** menu and run in a new terminal tab.
- Removing a worktree runs the **cleanup script**, and deletes the app-created branch when it has already been merged.

## Reviewing changes

After a turn that changed files finishes, its transcript shows an **Edited N files** card with each file marked added, modified, deleted, or renamed. **Review** opens the turn in the Git panel, either for the whole turn or an individual file. **Undo** restores files to their pre-turn state; it is blocked if a file changed after the turn, unavailable when a file exceeds the checkpoint size or quota, and disabled while the turn is still streaming.

Open the **Git** tab in the right panel's view switcher. The **Diff source** menu defaults to **Uncommitted** and also offers **Staged**, **Unstaged**, **Committed** (choose a commit), **Branch** (compare source and target branches), and **Turn** (a session turn's captured snapshot). A turn snapshot can expire.

Stage, unstage, and discard actions are available per file or for all files only in the live **Uncommitted**, **Staged**, and **Unstaged** scopes. Discard cannot be undone. The panel supports split or unified diffs, line wrapping, showing the full file, tree or list file views, and filtering changed files. If the workspace is not in a Git repository, the panel says so.

The commit popover offers **Commit** and **Commit and push**. Leave the message blank or choose **Generate commit message** to have the model selected in [Settings → Git](/docs/providers-and-settings/#git) write it.

## Panes and windows

- A session pane's **Split session** menu offers **Split Right**, **Split Down**, **Close Pane**, and **Close All**.
- **Open in a separate window** moves chat into its own window; **Move back to main window** returns it. The editor panel must be open to detach chat.
- The terminal supports multiple tabs with **New terminal**, **Find in terminal**, and **Restart**. Editor, PDF, terminal, and browser tabs each have a close button at the trailing edge: it stays visible on the active tab and appears when you hover the others.
- Use **Search files** in the editor's file tree. Its context menu offers **Add to Chat**, **Reveal in Finder** (where file-manager support is available), **Copy Path**, and **Copy Relative Path**.
- Workspace `.md` files in the editor toggle **Preview** / **Source** in the tab bar. (App-owned [notes](/docs/notes-and-issues/) use the notes editor, not this toggle.)
- For workspaces with several folders, **Edit workspace** manages **Source folders** with **Add folder**, **Make primary**, and **Remove folder**. Drop a folder onto the window to open it as a workspace.

## Collaboration and write modes

Per session (when the agent supports it):

| Control | Meaning |
| --- | --- |
| **Collaboration mode** | `default` for normal work; `plan` when the runtime supports a plan-first loop |
| **Write mode** | `read-only` vs `native-write` — whether the agent may change the workspace through its normal tools |
| **Permission mode** | How eagerly the agent auto-approves tools (agent-specific; see [Agents](/docs/agents/)) |

Prefer the narrowest mode that still completes the task.

## Keyboard shortcuts

Defaults are VS Code / Cursor-adjacent where that helps muscle memory. **Primary** means ⌘ on macOS and Ctrl on Windows/Linux. Customize under **Settings → Shortcuts**.

| Action | Default |
| --- | --- |
| File / quick open search | `Primary+P` |
| Open settings | `Primary+,` |
| Toggle left sidebar | `Primary+B` |
| Toggle right panel | `Primary+\` |
| Toggle editor fullscreen | `Primary+Shift+E` |
| Toggle chat dock | `Primary+J` |
| Toggle workspace search | `Primary+Shift+F` |
| Toggle browser design mode | `Primary+Shift+D` |
| Go back | `Primary+[` on macOS, `Alt+Left` on Windows and Linux |
| Go forward | `Primary+]` on macOS, `Alt+Right` on Windows and Linux |

**Back**, **Forward**, and **Open search** sit in the title bar. **Settings** is in the sidebar footer, and also opens with `Primary+,`. Back and Forward walk through the session, note, issue, deck, or panel view you had open, and through each settings section. In settings, **Back to app** leaves settings. Mouse side buttons do the same. The history is kept for this launch. In the browser client, the browser's own Back button is separate from these.

Send-key behavior for chat (Enter vs Primary+Enter for multiline) is configurable in settings. Keys for moving through a slide deck are listed on [Slide decks](/docs/decks/#presenting).

## Approvals in one place

Everything that needs you surfaces inside the session that asked for it: tool permission cards, agent questions, plan reviews, script-run proposals (with **Show script**, an agent limit, **Run** and **Discard**), and teammates that need input. On an assistant, **Needs you** in the [assistant overview](/docs/assistants/#overview) lists approvals, questions, and plans that are waiting, failed sessions, and routine runs that need you, failed, or paused, for that assistant and for work it delegated on this computer. Work on another computer is answered there; the delegated-work row names that computer. See [On another computer](/docs/assistants/#on-another-computer). The roster shows a status dot. Work and chat sessions you started yourself stay in their own lists. Nothing runs in the background without a visible state.

## Themes

Dark and light are both first-class. Prefer **system appearance** unless you pin a theme in settings. Theme parity is a product requirement, not a fallback afterthought. The dark theme is eased for long reading. Toasts use the neutral popover surface, and only the status icon carries color. The composer keeps rounded corners rather than a full pill.

When the main window supports it, **Settings → Appearance** adds **Translucent sidebar** and sliders for how much of the desktop shows through the sidebar and the main area. See [Appearance](/docs/providers-and-settings/#appearance).

## Browser design mode

The browser preview loads your dev server in tabs (**New tab** opens a blank one). Turn on **Design Mode** with the shortcut above or from the browser chrome, then:

- Click an element, or drag a region, to create an annotation with a screenshot.
- Add a comment and, optionally, a style preview of the change you want.
- Send the annotations to chat as one formatted message, so the agent sees exactly what you pointed at.

The annotation popover can be dragged out of the way; **Clear all annotations** resets the page.

## PDF reader

PDFs opened from the file tree open in the PDF reader instead of the code editor. A PDF attached to a conversation does the same, including one uploaded into that conversation: choose it under the assistant's **Conversation files**. Opening an attachment or a file from **Chat** also reveals **Conversation files**. The reader has a table of contents, page thumbnails, search, fit-width / fit-page zoom, page bookmarks, and highlights in four colors. Bookmarks and highlights are saved for that file. A file the reader refuses shows **Unable to open PDF** and **This PDF could not be opened in the reader.** Select text and choose **Add to Note** to quote it into a [note](/docs/notes-and-issues/).

## Decks

The **Decks** tab in the right panel lists slide decks, opens a 16:9 viewer with a filmstrip and speaker notes, and presents fullscreen or in presenter view. Rename, delete, and export from the list. See [Slide decks](/docs/decks/).

## What desktop owns

Local product data (notes, issues, decks, views, tags, links, search indexes, and related state) is written through the desktop **daemon** into app-owned storage. The public website and future team console do not replace that path for on-device work.

See [Workspaces and data](/docs/concepts/workspaces-and-data/).
