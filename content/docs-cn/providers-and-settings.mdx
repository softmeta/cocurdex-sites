Cocurdex 的大部分配置位于桌面应用的**设置**中。本页覆盖会影响 Agent 与模型行为的设置：Provider、MCP、网络、Git 和工作树环境。

## Provider 与模型

**设置 → 服务商** 管理 **Provider 配置**:一组带凭据和模型目录的命名服务端点。这些配置为内置 **Pi** 运行时和会话内模型控件提供数据。

一个 Provider 配置包含：

| 字段 | 含义 |
| --- | --- |
| Provider id / 名称 | 稳定 id 与显示名 |
| Base URL | 服务端点 |
| API 运行时 | `openai-completions`、`openai-responses`、`openai-codex-responses`、`anthropic-messages`、`google-generative-ai` 或 `mistral-conversations` |
| 认证 | 通过 Pi OAuth 登录的 Provider 账号，或由 Pi 管理的 API key |
| 模型 | 每个模型的 id、显示名、能力（agent / chat / reasoning / vision）、上下文与输出上限、每百万 token 成本 |
| 高级 | 自定义请求头、兼容性 JSON、思考等级映射 |

模板可为常见 Provider 自动填充端点；**Import JSON** 可批量导入 Provider 定义。一切在 UI 中管理，之后可用 CLI 验证：

```bash
cocurdex provider list
cocurdex provider models <provider-id>
```

外部 Agent CLI(`claude`、`codex`、`opencode`、`grok`)保留各自的认证——例如 Codex 的账号状态在 `~/.codex` 下。Provider 配置不替代它们；它为 Pi 和桌面端提供统一的模型目录。

## MCP 服务器

**设置 → MCP** 配置可供内置 **Pi** Agent 使用的 Model Context Protocol 服务器。仅当 Pi 使用其工具时服务器才会连接。

- 两种编辑方式：**表单**（名称、连接方式、命令/URL、参数、环境变量）和原始 **JSON**。
- JSON 结构是标准的 `mcpServers` 对象。
- 连接方式：**local** stdio(`command` + `args` + `env`)和 **remote** HTTP(`url`)。
- 变更在 Pi 会话启动时生效；已运行的会话保留其当前工具。

## 网络代理

**设置 → 网络** 控制应用的出站代理：

| 模式 | 行为 |
| --- | --- |
| `system` | 跟随系统 / 环境代理配置 |
| `manual` | 使用你提供的 HTTP / HTTPS / SOCKS(`allProxy`)地址与绕过列表(`noProxy`) |
| `off` | 直连出站流量，不应用应用代理 |

适用范围说明：

- 作用于 Agent 子进程（含 ACP）、应用与 daemon 的模型/API 请求，以及 Chromium 网络流量。
- **不**修改系统代理，也**不**强制集成终端使用这些设置。
- 代理 URL 以明文存储在应用设置中并传给 Agent 子进程——避免嵌入你不希望 CLI 子进程读到的凭据。
- 修改代理设置后重启活动中的 Agent 会话，使其获取新环境。

**Test connectivity** 通过应用的出站路径发送一次请求并回报出口 IP,可据此判断代理是否真正生效。

## Git

**设置 → Git** 选择用于生成提交信息的 Agent 与模型。提交信息留空时，所选模型根据暂存变更生成一条 Conventional Commits 主题。选择 **None** 则始终手动输入。

## 工作树环境

分两层：

- **设置 → 工作树**:托管工作树的根目录（留空使用默认位置），以及创建工作树前是否 fetch 远端。清单列出 Cocurdex 创建的每个检出、哪些会话在使用它，并提供删除 / 新建会话操作。
- **设置 → 项目 → 工作树设置**:按项目配置 **setup** 与 **cleanup** 脚本。setup 在 Cocurdex 创建工作树后自动运行(如 `pnpm install`);cleanup 在移除未使用的检出前运行。

同样的能力可用 `cocurdex worktree settings` 脚本化——见 [CLI](/zh-cn/docs/cli/#worktrees)。

## 设置助手

设置页有一个**助手**侧栏：一个带 `settings` Agent 工具的对话会话。让它「切换到深色模式」「检查我的通知设置」或者问「你能改哪些设置？」，它会替你读取并修改设置目录——包括项目工作树的 setup 与 cleanup 脚本。需要你确认的改动会先以提议形式给出。

任何主会话都能使用同样的工具；可选的 [`/cocurdex-settings`](/zh-cn/docs/skills/) skill 会教 Agent 用好它们。

## 诊断

**设置 → 诊断**（或菜单 **帮助 → 导出诊断日志…**）会把脱敏后的应用日志与运行时信息打包成一个文件，方便附到 GitHub Issue 中。复现问题时可以打开**详细诊断日志**记录更多细节；无论开关与否，日志都会脱敏。

**设置 → 常规** 还会显示本地 daemon 的状态（socket、协议版本、启动时间）并提供**重启**——当笔记、Issue 或 Agent 无响应时使用。

## 其他设置

| 分区 | 内容 |
| --- | --- |
| **常规** | 语言、通知、**Shell 命令**（把 `cocurdex` 安装到 `PATH`）、daemon 状态与重启 |
| **外观** | 主题（跟随系统 / 深色 / 浅色——双主题对齐是产品要求）、主题预设、字体 |
| **编辑器** | 编辑器字体与行为、代码缩略图 |
| **快捷键** | 可重新绑定的键盘快捷键；`null` 覆盖表示解绑 |
| **服务商** | Provider 配置与模型目录（见上文） |
| **适配器** | 各 Agent 的运行时探测与安装提示 |
| **角色** | 保存的 Agent 预设；见 [Agent](/zh-cn/docs/agents/) |
| **团队** | 可复用的[团队模板](/zh-cn/docs/teams/#团队模板) |
| **MCP** | 供 Pi 使用的 MCP 服务器（见上文） |
| **Skills** | 安装 / 移除 `cocurdex-*` 产品 skill 包 |
| **网络** | 出站代理（见上文） |
| **Git** | 提交信息模型（见上文） |
| **工作树** / **项目** | 托管工作树根目录与按项目脚本（见上文） |
| **已归档会话** | 浏览你归档的会话 |
| **诊断** | 导出诊断信息、详细日志 |
