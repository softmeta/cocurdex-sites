Cocurdex 的大部分配置位于桌面应用的**设置**中。本页覆盖会影响 Agent 与模型行为的设置：Agent CLI、Provider、MCP、网络、Git、工作树环境和设备。

## Agent CLI

**设置 → Agent CLI** 列出新建会话时可以选用的所有 Agent。每一项会显示探测到的版本和状态（**内置**、**可用**、**未安装**、**需要升级**、**有更新**、**需要登录**）、可复制的安装命令、文档链接，以及——对能上报的 Agent——你的套餐用量。未安装的 Agent 收在 **未安装（N）** 里，展开才看得到。新建会话的 Agent 菜单会藏起这些未安装的 Agent；你已经选中的 Agent 即使后来被卸掉，仍会留在菜单里。**更新到 v…** 安装 ACP Registry 上更新的构建。支持登录的 Registry Agent 提供**登录**和**退出登录**。**从 ACP Registry 添加**可以安装更多 Agent,或用你自己的命令注册一个。见 [Agent](/zh-cn/docs/agents/#acp-registry-agent)。

```bash
cocurdex agent updates
cocurdex agent update <agent>
cocurdex agent login <agent>
```

同一页的**运行上限**限制同时执行的 agent 运行数量。超出上限的委派运行（队友和脚本编排的子 Agent）会排队等待；你自己发起的运行不受限制。

| 控件 | 含义 |
| --- | --- |
| **并发运行数** | 所有会话合计的 agent 运行数（1–64） |
| **每个 agent 并发运行数** | 同一 agent 同时运行的数量（1–64） |
| **委派运行超时** | 队友或子 agent 超过该分钟数会被停止；留空表示不限时 |

## Provider 与模型

**设置 → 服务商** 管理 **Provider 配置**:一组带凭据和模型目录的命名服务端点。这些配置为内置 **Pi** 运行时和会话内模型控件提供数据。

一个 Provider 配置包含：

| 字段 | 含义 |
| --- | --- |
| Provider id / 名称 | 稳定 id 与显示名 |
| Base URL | 服务端点 |
| API 运行时 | `openai-completions`、`openai-responses`、`openai-codex-responses`、`anthropic-messages`、`google-generative-ai` 或 `mistral-conversations` |
| 认证 | 通过 Pi OAuth 登录的 Provider 账号，或由 Pi 管理的 API key |
| 模型 | 每个模型的 id、显示名、能力（agent / chat / reasoning / vision）、上下文与输出上限、每百万 token 成本 |
| 高级 | 自定义请求头、兼容性 JSON、思考等级映射 |

模型一行上的**模型参数**可以改 API 运行时、上下文和输出上限、能力、推理，以及高级 JSON。内置目录里的模型也可以改：你改过的字段在目录更新后仍然保留，这一行会标为**已修改**。**恢复默认**还原目录里的值。不能在这里添加或删除内置模型。

模板可为常见 Provider 自动填充端点；**Import JSON** 可批量导入 Provider 定义。一切在 UI 中管理，之后可用 CLI 验证：

```bash
cocurdex provider list
cocurdex provider models <provider-id>
```

Provider 配置与模型同样可以脚本化：`cocurdex provider add|update|login|key|model|default|import|export`——见 [CLI](/zh-cn/docs/cli/#provider)。

外部 Agent CLI(`claude`、`codex`、`opencode`,以及 `cursor-agent`、`grok` 等 ACP Registry Agent)保留各自的认证——例如 Codex 的账号状态在 `~/.codex` 下。Provider 配置不替代它们；它为 Pi 和桌面端提供统一的模型目录。

## MCP 服务器

**设置 → MCP** 是 Cocurdex 提供给你的 Agent 的工具服务器。新会话会用上改动；正在运行的会话保留它已经有的工具。

- **表单**（名称、本地命令或远程 URL、参数、环境变量或请求头）和原始 **JSON**。JSON 结构是标准的 `mcpServers` 对象。
- 服务器名称只能包含字母、数字、`_` 和 `-`。
- **Agent** 选择哪些 Agent 会拿到这台服务器。它们自己的 MCP 配置不会被改动。有些服务器只有 Pi 能用——例如设置了工作目录、用命令取值，或通过 Pi 的服务商登录。这一行会写明原因。
- **从其他 Agent 导入**读取这台电脑上 Claude Code、Codex、Cursor、OpenCode 或 Antigravity 已经配置的服务器，包括项目级配置。每一项都要你确认。也可以拖入或粘贴 JSON。
- 服务器要求登录时使用**登录**。**测试连接**列出它的工具。
- 定义在磁盘文件里的项目服务器在这里是只读的；要改就去改那个文件。
- **高级 → 工具暴露方式**可以是**直接暴露**（每个工具都在 Agent 的工具列表里）、**按需加载**（Agent 搜索时才加载）、**代码模式**（Pi 从生成的代码里调用），或**隐藏**。

```bash
cocurdex mcp list
cocurdex mcp import --from codex
```

其余命令见 [CLI](/zh-cn/docs/cli/#mcp-服务器)。

## 网络代理

**设置 → 网络** 控制应用的出站代理：

| 模式 | 行为 |
| --- | --- |
| `system` | 跟随系统 / 环境代理配置 |
| `manual` | 使用你提供的 HTTP / HTTPS / SOCKS(`allProxy`)地址与绕过列表(`noProxy`) |
| `off` | 直连出站流量，不应用应用代理 |

适用范围说明：

- 作用于 Agent 子进程（含 ACP）、应用与 daemon 的模型/API 请求，以及 Chromium 网络流量。
- **不**修改系统代理，也**不**强制集成终端使用这些设置。
- 代理 URL 以明文存储在应用设置中并传给 Agent 子进程——避免嵌入你不希望 CLI 子进程读到的凭据。
- 修改代理设置后重启活动中的 Agent 会话，使其获取新环境。

**Test connectivity** 通过应用的出站路径发送一次请求并回报出口 IP,可据此判断代理是否真正生效。

## Git

**设置 → Git** 选择用于生成提交信息的 Agent 与模型。提交信息留空时，所选模型根据暂存变更生成一条 Conventional Commits 主题。选择 **None** 则始终手动输入。

## 工作树环境

分两层：

- **设置 → 工作树**:托管工作树的根目录（留空使用默认位置），以及创建工作树前是否 fetch 远端。清单列出 Cocurdex 创建的每个检出、哪些会话在使用它，并提供删除 / 新建会话操作。
- **设置 → 工作区 → 工作树设置**:按工作区配置 **setup** 与 **cleanup** 脚本以及 **Actions**。setup 在 Cocurdex 创建工作树后于后台运行(如 `pnpm install`)，会话首轮会等待它完成；cleanup 在移除未使用的检出前运行。Actions 是具名命令（例如「开发服务器」→ `npm run dev`），显示在会话的 **…** 菜单中，每个都在新的终端标签中运行。**让 Agent 分析**会让 Agent 检查仓库，并提出两段脚本供你批准。

同样的能力可用 `cocurdex worktree settings` 脚本化——见 [CLI](/zh-cn/docs/cli/#工作树)。

## 设备

**设置 → 设备** 可在本机浏览器中打开同一主机，或把另一台设备按权限配对。见[设备与本地网页](/zh-cn/docs/devices-and-web/)。

## 设置助手

设置页有一个**助手**侧栏：一个带 `settings` Agent 工具的对话会话。让它「切换到深色模式」「检查我的通知设置」或者问「你能改哪些设置？」，它会替你读取并修改设置目录——包括项目工作树的 setup 与 cleanup 脚本。需要你确认的改动会先以提议形式给出。

任何主会话都能使用同样的工具；可选的 [`/cocurdex-settings`](/zh-cn/docs/skills/) skill 会教 Agent 用好它们。

## 应用更新

**设置 → 关于**会显示已安装的版本，并提供**检查更新**。更新通道可选**稳定**或**测试**；测试版可能不稳定，切回稳定通道时也可能安装较旧的版本。

更新下载完成后，会出现**发现新版本**卡片，其中有**更新并重启**、**稍后**和**查看更新日志**。自动更新仅在安装版应用中可用。

## 诊断

**设置 → 诊断**（或菜单 **帮助 → 导出诊断日志…**）会把脱敏后的应用日志与运行时信息打包成一个文件，方便附到 GitHub Issue 中。复现问题时可以打开**详细诊断日志**记录更多细节；无论开关与否，日志都会脱敏。同一组操作是 `cocurdex diagnostics export` 和 `cocurdex diagnostics level debug|info`。`cocurdex daemon health` 打印进程、内存和正在进行的工作。

## Daemon

**设置 → 常规 → Daemon** 显示本地 daemon（socket、协议版本、启动时间）。未运行时按钮是**启动**，运行中是**重启**。笔记、Issue、演示文稿或 Agent 无响应时，用**重启**把它换掉。打开**后台常驻**后，状态行会写**运行中（…），后台常驻，退出应用后继续运行。**

**后台常驻**默认关闭。打开后，退出桌面应用时 daemon 继续为 CLI 和已配对设备服务，并在登录时启动：macOS 使用 LaunchAgent，Windows 使用 Run 键，Linux 使用 XDG autostart。关闭后，退出应用会停掉它自己管理的 daemon。终端里的同一开关是 `cocurdex daemon background on|off|status [--json]`。见 [CLI](/zh-cn/docs/cli/#daemon-与工作区)。

## 查找设置

设置侧边栏顶部有一个**搜索设置**框。框里有文字时，**清空搜索**会把它清掉。没有匹配项时，列表显示**没有匹配的设置**。

在 macOS 上按 Command+F，在 Windows 和 Linux 上按 Ctrl+F，可以聚焦这个框。Escape 清空搜索。上、下方向键在结果之间移动，Enter 打开当前选中的一项。

搜索会匹配设置分区和单个设置（包括每一条快捷键）的标题、分组、分区和说明。英文和简体中文都会参与匹配，所以无论界面用的是哪种语言，`proxy` 和 `代理` 都能搜到。当前窗口不显示的设置不会出现在结果里。结果按分区分组。选中一项会打开该分区。选中某个设置时，还会把对应的行滚进视野并短暂高亮。如果这一行在当前状态下不在页面上——**代理模式**不是 `manual` 时的手动代理字段——则会滚到用来展开这些字段的**代理模式**那一行。

## 外观

**设置 → 外观**用来设置主题（**浅色**、**深色**或**系统**）、配色主题预设，以及界面与代码字体。

在主桌面窗口上，如果系统可以绘制窗口材质，这一页还会显示**半透明侧边栏**，默认打开：**让侧边栏透出背后的桌面。** macOS 使用 sidebar vibrancy。Windows 11 22H2 或更新版本（内部版本 22621 或更高）使用 Mica。Linux、较旧的 Windows、[网页客户端](/zh-cn/docs/devices-and-web/)，以及用**在独立窗口中打开**分出去的聊天窗口，都保持不透明，这些控件也会隐藏。系统要求降低透明度时，即使控件仍然显示，界面也保持不透明。

开关打开后会出现两根滑杆。拖动时立刻预览，松开滑杆才保存。

| 控件 | 范围 | 默认 | 含义 |
| --- | --- | --- | --- |
| **侧边栏透明度** | 0–100% | 12% | 侧边栏透出桌面的程度 |
| **主区域透明度** | 0–100% | 10% | 主区域透出桌面的程度 |

**主区域透明度**同时作用于对话栏、右侧面板和设置内容。窗口材质跟随主题（**浅色**、**深色**或**系统**）。[设置助手](#设置助手)接受同样的整数范围：`sidebarTransparency` 和 `contentTransparency` 为 0 到 100，默认分别是 12 和 10。它们只在带窗口材质的桌面端生效。

窗口材质显示时，编辑器的**代码 MiniMap**保持不透明。它与编辑器吸顶装饰使用同一块实色表面，因此不会在透明的编辑器上显示成黑色。
