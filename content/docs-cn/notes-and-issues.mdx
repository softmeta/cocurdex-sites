笔记和 Issue 是 Cocurdex 中的一等**产品记录**。它们存放在应用私有存储(`cocurdex.sqlite`)中，而不是在仓库里隐式双写一棵 Markdown 树。

## 为什么应用私有

| 能力 | SQLite 帮了什么 |
| --- | --- |
| 稳定 id | 标题和文件夹可以改名而不破坏链接 |
| 事务 | 多行更新保持一致 |
| 版本号 | 可以检测到过期写入 |
| 全文搜索 | 笔记和 Issue 共享一个搜索索引 |
| 反向链接 / 标签 | 规范化图谱，而非路径爬取 |

Markdown 之后仍可用于**显式**导入导出。在此之前，请把 CLI 和桌面 UI 当作唯一受支持的写入方。

## 笔记

笔记支持：

- 层级**文件夹**与笔记页（含**新建子页面**）
- 与正文分开的**笔记标题**字段
- 以块编辑的 Markdown 正文
- **标签**
- 笔记之间的**反向链接**
- 可选关联到某个**工作区**

笔记侧栏按**个人**笔记和各工作区分组。拖动笔记，或用**移动到**，可以改它的父级。双击标题，或选择**重命名**，即可就地改名——[演示文稿](/zh-cn/docs/decks/)列表用的是同一套操作。

### 桌面编辑器

标题在正文上方。在标题里按 **Enter** 或 **Down** 会把光标移进正文。

正文占位是 **开始写作，或按 “/” 插入块…**。`/` 打开**插入块**：

| 块 | 插入 |
| --- | --- |
| 正文 / 标题 1–3 | 段落或标题 |
| 无序列表 / 有序列表 / 待办列表 | 列表，含勾选框 |
| 引用 / 代码块 / 分隔线 | 常见 Markdown 块 |
| **表格** | 可编辑表格 |

表格边缘有点击/拖动手柄（**点击添加，拖动可添加多个**）。行、列菜单覆盖插入、删除、**复制**、**清空内容**、对齐（左对齐 / 居中 / 右对齐）、**升序排列** / **降序排列**，以及**删除表格**。如果笔记的最后一块是表格，点击它下方的空白会插入一个空行，方便继续写。

保存状态显示为 **保存中…** / **已保存**。保持稳定的笔记标题和链接，这样 Agent 和人之后能找到同一条记录。

在 [PDF 阅读器](/zh-cn/docs/desktop/#pdf-阅读器)里看文档时，选中文字并选择**加入笔记**，即可把它摘录进笔记。

### CLI

```bash
cocurdex note list
cocurdex note create --title "Architecture notes" --body "## Context\n..."
cocurdex note show <id>
cocurdex note update <id> --body "..."
cocurdex note move <id> --parent <note-id>
cocurdex note move <id> --root
cocurdex note backlinks <id>
cocurdex note tags
cocurdex note delete <id>
```

`--body -` 从 stdin 读 Markdown；`--body-file <path>` 从文件读。

创建文件夹：

```bash
cocurdex note create --title "PRDs" --folder
```

## Issue

Issue 是产品中的 **todo / ticket / 看板卡片**模型。叫法不同，存储是同一个池：

| 你说 | 同一模型 |
| --- | --- |
| issue | issue |
| todo | issue |
| ticket | issue |

### 默认看板列（状态）

| Id | 标题 |
| --- | --- |
| `backlog` | Backlog |
| `doing` | Doing |
| `review` | Review |
| `done` | Done |

### 默认优先级

| Id | 标题 |
| --- | --- |
| `urgent` | Urgent |
| `high` | High |
| `medium` | Medium |
| `low` | Low |
| `none` | No priority |

### 视图

内置视图 id 是 **`project`**。Issue 侧栏列出**视图**，以及快捷入口：**进行中**、**全部 Issue**、**Backlog** 和 **Agent 在做**。视图可以按**状态**或**优先级**分组，布局可以是**看板**或**列表**。拖动卡片（和列）会更新被分组的字段。**视图显示**只作用于该视图。用**添加视图**再建视图；删除视图不会删除 Issue。

打开一条 Issue 可编辑标题、描述、**标签**、**父 issue** / **子 issue**、**关联**（阻塞 / 相关 / 重复）、已链接的 **Agent 会话**、评论，以及**动态**记录。筛选可以隐藏已完成和已取消的卡片，或按工作区和标签收窄。

列表视图以及创建/移动操作都经由 daemon（桌面 UI 或 CLI）——不要手工编造 issue id。

```bash
cocurdex issue views
cocurdex issue list
cocurdex issue list --status doing [--label <name>] [--parent <id>] [--open]
cocurdex issue create --title "Wire download artifacts" --status backlog --priority high [--labels <ids>] [--parent <id>]
cocurdex issue update <id> [--title <title>] [--body <text>] [--status <column>] [--priority <id>]
cocurdex issue move <id> doing
cocurdex issue show <id> [--detail]
cocurdex issue comment <id> --body "Shipped on main"
cocurdex issue relate <id> blocks|related|duplicate <id>
cocurdex issue unrelate <id> blocks|related|duplicate <id>
cocurdex issue labels
cocurdex issue label create --name "release" [--color <color>]
cocurdex issue label delete <id|name>
cocurdex issue delete <id>
```

## 搜索

```bash
cocurdex search "download"
cocurdex search "auth" --kind note
cocurdex search "release" --kind issue --workspace <workspace-id>
```

## 与 Agent 协作

直接在输入框里把 Issue 或笔记交给 Agent:**+ → Issue** 或 **+ → 笔记** 会把它作为标签附加上去，Agent 在提示词里就能拿到完整的标题和正文。在对话记录里点击该标签即可打开对应记录。

产品 Skills(`/cocurdex-note`、`/cocurdex-issue` 等)调用同一套 CLI,因此 Agent 不需要打开 SQLite。见 [Skills](/zh-cn/docs/skills/)。

产品工作的推荐循环：

```text
/cocurdex-note(PRD 或 spec)  →  /cocurdex-issue  →  /cocurdex-ship
```

PRD 和 spec 就是普通笔记，默认存为**私有笔记**。要发布到仓库中需要明确的用户请求——绝不要认为「打开工作区」就等于「把产品文档写进仓库」。

## 在手机上

iOS 与 Android 应用可以阅读工具栏里那台电脑上的笔记和 Issue。配对时需要**读取**权限。这一版里两个标签都是只读的：不能新建，没有收件箱标签，没有看板，也没有**动态**和评论。手机上也不能把笔记或 Issue 交给 Agent。要附加给 Agent，仍在桌面输入框里用 **+ → 笔记** 或 **+ → Issue**。应用的配对见[设备与本地网页](/zh-cn/docs/devices-and-web/#原生应用)。

### Issues 标签

**Issues** 按状态分组，进行中的在前。默认看板上，**Doing** 和 **Review** 排在 **Backlog** 和 **Done** 上面。分组标题是状态名加数量，例如 **Doing 2**。工具栏菜单按工作区筛选，标题是工作区名称，或**全部工作区**。**搜索 issue** 按标题或标识符匹配。下拉可以刷新。

还没有跟踪任何 Issue 时显示**没有 issue**——**在**该电脑**上跟踪的 issue 会显示在这里。** 搜索没有命中时显示**没有与“…”匹配的 issue**。列表加载失败时，画面是**无法从**该电脑**加载 issue**，并提供**重试**。

每一行显示标题，下面是标识符和标签。打开后，顶栏是标识符。页面显示标题、有描述时按 Markdown 渲染的描述，然后是**状态**、**优先级**和**标签**（没有标签时为**无**）。有已链接的会话时，**Agent 会话**会列出它们，点一条即可打开。没有标题的会话显示**未命名会话**。有子 issue 时，标题是已完成数比总数，例如 **子 issue 1/3**，页面会列出这些子 issue。已删除的 Issue 显示**这个 issue 已在电脑上删除。**

### 笔记标签

**笔记**按工作区收成一棵缩进的树。没有工作区的笔记归在**未归属工作区**下。文件夹留在树里；打开一篇笔记即可阅读。**搜索笔记**按标题匹配。每个工作区里的命中项是一份平铺列表，最新的在前。下拉可以刷新。

这台电脑还没有笔记时显示**没有笔记**——**在**该电脑**上写的笔记会显示在这里。** 搜索没有命中时显示**没有与“…”匹配的笔记**。列表加载失败时，画面是**无法从**该电脑**加载笔记**，并提供**重试**。

笔记页显示标题、工作区、距上次修改的时间，以及 Markdown 正文——渲染方式和会话记录相同。空笔记显示**这篇笔记是空的。** 已删除的笔记显示**这篇笔记已在电脑上删除。**

## 不要做的事

- 不要把项目下的路径当作 Issue 身份
- 不要手工编辑 `cocurdex.sqlite`
- 不要在脚本里编造 issue 或 note id——通过 CLI 创建并保存返回的 id
- 除非你自己负责一条显式的导出流程，否则不要「保险起见」双写 Markdown 副本
