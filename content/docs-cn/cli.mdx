**`cocurdex` CLI** 是应用私有产品数据和 daemon 操作受支持的命令行边界。外部工具和 Agent 应该使用 CLI,而不是读取私有数据库文件。

大多数数据和会话命令需要**桌面 daemon**。打开桌面应用会启动它。随安装包提供的 CLI 会在没有 daemon 监听时自己启动 daemon，因此桌面窗口关掉后命令仍然可用。如果这个启动器拉不起来，打开桌面应用后再试。

**后台常驻**（**设置 → 常规 → Daemon**）默认关闭。打开后，退出应用时 daemon 继续为 CLI 和已配对设备服务，并在登录时启动。关闭后，退出桌面应用会停掉它自己管理的 daemon。见 [Daemon 与工作区](#daemon-与工作区)。

## 安装

当 CLI 随桌面应用打包时，从 **设置 → 常规 → Shell 命令** 安装启动器，让 `cocurdex` 出现在 `PATH` 上。

```bash
cocurdex --version
cocurdex --help
```

在 monorepo 开发中，使用 workspace 里的 CLI 包(`apps/cli`)。

### 找到桌面二进制

打开流程需要 Cocurdex / Electron 二进制。解析顺序包括：

1. `COCURDEX_ELECTRON` 环境变量
2. 正运行在 Electron / 打包应用内
3. monorepo 下开发用的 `node_modules/electron`
4. 常见 macOS 安装路径(`/Applications/Cocurdex.app/...`)

解析失败时，先打开一次桌面应用并安装 CLI 启动器，或设置 `COCURDEX_ELECTRON`。

平台说明：

- **Linux AppImage**——启动器运行一份稳定的 CLI 副本，AppImage 挂载点消失后依然可用。
- **Windows**——启动器是用户 `PATH` 上的一个 shim;卸载 Cocurdex 时会一并移除 shim 及其 `PATH` 条目。

## 笔记

```bash
cocurdex note list [--json]
cocurdex note show <id> [--json]
cocurdex note create --title <title> [--body <markdown>] [--parent <id>] [--workspace <id>] [--folder] [--json]
cocurdex note update <id> [--title <title>] [--body <markdown>] [--json]
cocurdex note move <id> --parent <note-id> | --root [--json]
cocurdex note delete <id> [--json]
cocurdex note backlinks <id> [--json]
cocurdex note tags [note-id] [--json]
```

| Flag | 含义 |
| --- | --- |
| `--title` | 创建时必填 |
| `--body` | Markdown 正文（`-` 从 stdin 读取）。`--body-file <path>` 从文件读取 |
| `--root` | 在 `move` 时把笔记提升到侧栏根级 |
| `--folder` | 创建文件夹节点而非笔记 |
| `--parent` | 父级笔记/文件夹 id |
| `--workspace` | 可选的工作区关联 |

更新在底层使用乐观并发（revision）——始终优先用 CLI/桌面端，而非编辑 SQLite。

## Issue

默认视图 id 是 `project`,除非传入 `--view`。

```bash
cocurdex issue list [--status <column>] [--label <name>] [--parent <id>] [--open] [--view <id>] [--json]
cocurdex issue show <id> [--detail] [--view <id>] [--json]
cocurdex issue create --title <title> [--status <column>] [--priority <id>] [--body <markdown>|--body-file <path>] [--workspace <id>] [--parent <id>] [--labels <ids>] [--view <id>] [--json]
cocurdex issue update <id> [--title <title>] [--body <markdown>|--body-file <path>] [--status <column>] [--priority <id>] [--workspace <id>|none] [--parent <id>|none] [--labels <ids>] [--view <id>] [--json]
cocurdex issue move <id> <column> [--view <id>] [--json]
cocurdex issue comment <id> --body <markdown>|--body-file <path> [--json]
cocurdex issue relate <id> blocks|related|duplicate <id> [--json]
cocurdex issue unrelate <id> blocks|related|duplicate <id> [--json]
cocurdex issue labels [--json]
cocurdex issue label create --name <name> [--color <color>] [--json]
cocurdex issue label delete <id|name> [--json]
cocurdex issue delete <id> [--view <id>] [--json]
cocurdex issue views [--json]
```

默认**状态**：`backlog`（Backlog）、`todo`（Todo）、`doing`（In Progress）、`review`（In Review）、`done`（Done）、`canceled`（Canceled）。每个状态有一个类别：`backlog`、`unstarted`、`started`、`completed` 或 `canceled`。
默认**优先级**列：`urgent`、`high`、`medium`、`low`、`none`。

状态、标签和已保存的视图：

```bash
cocurdex issue statuses [--json]
cocurdex issue status create --name <name> --category backlog|unstarted|started|completed|canceled [--color <color>]
cocurdex issue status update <id|name> [--name <name>] [--category <category>] [--color <color>]
cocurdex issue status move <id|name> --position <n>
cocurdex issue status delete <id|name>
cocurdex issue label update <id|name> [--name <name>] [--color <color>]
cocurdex issue view update <id> [--title <title>] [--group-by status|priority|label|workspace|parent] [--layout board|list] [--show-empty true|false] [--properties <a,b>]
cocurdex issue move <id> <column> [--from <column>]
```

`create`、`update` 和 `comment` 的正文与笔记相同：`--body -` 从 stdin 读取，`--body-file <path>` 从文件读取。未知参数会被拒绝，事项保持不变。错误是 `Unknown flag --<name> for "issue <action>". Accepted flags: ...`。

`--from` 指出卡片原来所在的标签，并且只改那一个标签。`--properties` 接受 `identifier`、`status`、`priority`、`labels`、`workspace`、`parent`、`description`、`created` 和 `updated`。见[笔记与 Issue](/zh-cn/docs/notes-and-issues/#issue)。

示例：

```bash
cocurdex issue create --title "Fix download page" --status backlog --priority high
cocurdex issue move <id> doing
cocurdex issue list --status doing
```

## 演示文稿

演示文稿是应用私有记录：用 Markdown 写入，得到 16:9 的幻灯片，并检查溢出、空白页和未知槽位。版式、主题、放映和 `/cocurdex-deck` skill 见[演示文稿](/zh-cn/docs/decks/)。

```bash
cocurdex deck list [--json]
cocurdex deck show <id> [--json]
cocurdex deck create [--title <title>] [--markdown-file <path|-> | --content-file <path|->] [--workspace <id>] [--json]
cocurdex deck update <id> [--title <title>] [--markdown-file <path|-> | --content-file <path|->] [--expected-revision <n>] [--json]
cocurdex deck edit <id> --ops-file <path|-> [--expected-revision <n>] [--json]
cocurdex deck image <id> --slide <slideId> --file <path.png|path.jpg> [--alt <text>] [--replace <elementId>] [--expected-revision <n>] [--json]
cocurdex deck check <id> [--json]
cocurdex deck export <id> --output <path.pptx|path.pdf> [--format pptx|pdf] [--json]
cocurdex deck import <file.pptx> [--title <title>] [--workspace <id>] [--json]
cocurdex deck read <file.pptx> [--json]
cocurdex deck delete <id> [--json]
```

| Flag | 含义 |
| --- | --- |
| `--markdown-file` / `--content-file` | Markdown 源，或结构化的演示文稿 JSON。`-` 从 stdin 读取。二者互斥，也都可以省略。都不传时，创建得到没有幻灯片的演示文稿，更新则保留现有幻灯片 |
| `--ops-file` | 编辑 ops 的 JSON 数组，或 `{ "ops": [ ... ] }`。按顺序应用；有一步失败则不会保存 |
| `--expected-revision` | 来自 `deck show` 的修订号。过期的写入会失败并提示 `Deck was modified` |
| `--output` / `--format` | 导出路径。格式为 `pptx` 或 `pdf`，也可由输出文件的扩展名决定 |
| `--workspace` | 创建或导入时可选的工作区 id |
| `--slide` / `--file` / `--alt` / `--replace` | 添加 PNG 或 JPEG（最大 20 MB），或换掉一张并保留其框 |

`deck list` 打印 id、标题、幻灯片数量、修订号和更新时间。`deck show` 带上检查问题。`deck read` 把 PowerPoint 文件打成 Markdown，不会新建演示文稿。`deck import` 新建演示文稿，原文件保持不动。单独一行 `---` 用来分页；以 `Notes:` 或 `备注：` 开头的段落开始演讲者备注。

## 助理

个人助理、委派工作、应用、例行任务和收件箱。完整说明见[助理](/zh-cn/docs/assistants/)。`<persona>` 或 `<routine>` 可以是 id、唯一的 id 前缀或名称。

```bash
cocurdex persona list [--json]
cocurdex persona show <persona> [--json]
cocurdex persona create --name <name> [--provider <id> --model <id>] [--description <text>] [--instructions <text>|--instructions-file <path>] [--soul <text>|--soul-file <path>] [--json]
cocurdex persona update <persona> [--name <name>] [--provider <id> --model <id>] [--description <text>] [--instructions <text>|--instructions-file <path>] [--soul <text>|--soul-file <path>] [--pin|--unpin] [--mute|--unmute] [--json]
cocurdex persona duplicate <persona> --name <name> [--json]
cocurdex persona delete <persona>
cocurdex persona send <persona> <message> [--wait] [--timeout <seconds>] [--json]
cocurdex persona thread <persona> [--limit <n>] [--json]
cocurdex persona work catalog [--json]
cocurdex persona work list <persona> [--json]
cocurdex persona work start <persona> --workspace <id|name> --prompt <text>|--prompt-file <path> [--title <title>] [--role <role>|--team <template>] [--worktree] [--json]
cocurdex persona work send <persona> <session-id> <message> [--json]
cocurdex persona work stop <persona> <session-id> [--json]
cocurdex routine list [--persona <persona>] [--json]
cocurdex routine show <routine> [--json]
cocurdex routine create --persona <persona> --name <name> (--prompt <text>|--prompt-file <path>) (--every <minutes>|--at <HH:MM> [--days <mon,wed|weekdays|weekends>]) [--tz <zone>] [--access read-and-draft|full] [--deliver inbox|push|silent] [--json]
cocurdex routine update <routine> [--name <name>] [--prompt <text>|--prompt-file <path>] [--every <minutes>|--at <HH:MM> [--days <days>]] [--tz <zone>] [--access read-and-draft|full] [--deliver inbox|push|silent] [--json]
cocurdex routine pause|resume <routine> [--json]
cocurdex routine run <routine> [--wait] [--timeout <seconds>] [--json]
cocurdex routine runs [<routine>] [--limit <n>] [--json]
cocurdex routine delete <routine>
cocurdex inbox [list] [--json]
cocurdex inbox read <item-id> [--json]
cocurdex inbox brief [--tz <zone>] [--json]
cocurdex inbox brief post [--tz <zone>] [--locale en-US|zh-CN] [--json]
```

个人助理始终跑在 Pi 上。`persona create` 和 `persona update` 没有 `--agent` 参数。`--provider` 和 `--model` 要一起给出。`persona send --wait` 打印回复（默认超时 600 秒）。`persona delete` 会删除那个助理，包括默认助理：列表里的下一个成为默认助理；一个都不剩时列表保持为空。`routine create` 需要 `--prompt` 或 `--prompt-file`，以及 `--every`（至少 5）或 `--at` 其中之一。`--access` 为 `read-and-draft`（默认）或 `full`。`inbox read` 把该项的线程标为已访问。没有可报告的内容时，`inbox brief` 打印 `Nothing to brief today.` `inbox brief post` 把今日简报写入默认助理的主线程。`--locale` 为 `en-US` 或 `zh-CN`；省略则沿用上次发布所用的语言。没有新内容可发布时打印 `Nothing new to post.`

`persona work` 把仓库工作交给一个工作会话。`catalog` 列出工作区、已保存的 Agent 角色和团队模板。`list` 打印 `sessionId`、`title`、`workspaceName`、`agentType` 和 `state`。`--workspace` 是 id 或名称。名称匹配到不止一个工作区时失败，提示 `Several workspaces are named "<name>"; pass its id.` `--role` 和 `--team` 二选一（`Pass either an agent role or a team template, not both.`）。`--prompt-file` 从文件读取任务。`--worktree` 使用一棵新的 git 工作树。`send` 和 `stop` 只接受这个助理委派过的会话（`No work session you delegated has this id.`）。见[委派工作](/zh-cn/docs/assistants/#委派工作)。

## Daemon 与工作区

```bash
cocurdex daemon status
cocurdex daemon background on|off|status [--json]
cocurdex workspace list
```

`daemon background` 就是 **设置 → 常规 → Daemon → 后台常驻**。

- `on` 让 daemon 在退出 Cocurdex 后继续运行，并登记为登录时启动：macOS 用 LaunchAgent，Windows 用 Run 键，Linux 用 XDG autostart。
- `off` 移除该登录项。之后退出桌面应用会停掉它自己管理的 daemon。
- `status` 打印一行。更改成功后，`on` 和 `off` 也打印这一行：
  - 后台模式关闭：退出 Cocurdex 时 daemon 停止
  - 后台模式开启：退出 Cocurdex 后 daemon 继续运行，并在登录时启动
  - 后台模式已开启，但登录项缺失；再运行 `cocurdex daemon background on` 可以补回
  - 源码构建不可用。终端原文是 `Background mode is not available for this daemon (source build)`。此时 **设置 → 常规 → Daemon** 不显示这个开关，`on` 或 `off` 会失败，原文是 `Background mode is not available for this daemon`
- `--json` 打印 `enabled`、`available` 和 `registered`。

只有这台电脑能更改这项设置。已配对设备会被拒绝，原文是 `Only this computer can change background mode`。`daemon status` 和 `daemon health` 也列在[诊断](#诊断)下。

## 设备与本地网页

打印本地网页客户端 URL。daemon 必须在运行。**后台常驻**让它在退出桌面应用后继续提供服务，打包的 CLI 也会在它没在跑时启动它：

```bash
cocurdex web [--json]
```

把另一台设备配对到主机 daemon。完整模型见[设备与本地网页](/zh-cn/docs/devices-and-web/)。

```bash
cocurdex host status [--json]
cocurdex host remote enable [--port <port>] [--keep-awake on|off] | disable [--json]
cocurdex host pair --label <name> [--scopes read,interact,approvals] [--ttl <minutes>] [--json]
cocurdex host pairings [--json]
cocurdex host pairing cancel <pairing-id>
cocurdex host devices [--json]
cocurdex host approve <device-id> --code <safety code>
cocurdex host revoke <device-id>
cocurdex host scopes <device-id> --scopes <list>
cocurdex host traffic [--reset] [--json]
cocurdex host relay set [official|<url>] [--relay-only on|off] [--credential <file>]
cocurdex host relay off
cocurdex host push set <url> | off
cocurdex host push status [--json]
cocurdex host audit [--limit <n>] [--json]
```

`--scopes` 是逗号分隔的 `read`、`interact`、`execute`、`files.read`、`files.write`、`git.destructive`、`approvals`、`credentials`、`devices`。默认配对权限是 `read,interact,approvals`。`host.admin` 不能授出。`host approve` 输入正在等待的设备上显示的安全码。

## 工作树

托管的 git 工作树为会话提供工作区仓库的隔离检出。

```bash
cocurdex worktree list [--json]
cocurdex worktree settings [--root <path>] [--fetch|--no-fetch] [--json]
cocurdex worktree create --workspace <id|path> --branch <name> [--start-point <rev>] [--json]
cocurdex worktree remove --workspace <id|path> --path <worktree-path> [--json]
```

不带 flags 的 `worktree settings` 打印当前设置；传 `--root` 和/或 `--fetch`/`--no-fetch` 则更新。`--root` 设置 Cocurdex 创建托管工作树的目录（置空则恢复默认位置）；`--fetch` 控制创建工作树之前是否先 fetch 仓库。

```bash
cocurdex session send <session-id> <prompt>

cocurdex session handoffs <session-id> [--json]

```

| Flag | 必填场景 | 含义 |
| --- | --- | --- |
| `--workspace` | create，以及 tui 创建时 | 工作区 id 或文件系统路径 |
| `--agent` | 可选 | Agent id：`claude-agent`、`codex`、`opencode`、`pi`，或已安装的 ACP Registry Agent，如 `acp:cursor`、`acp:devin`、`acp:grok-build` |
| `--provider` | 可选，须与 `--model` 同时给出 | `provider list` 中的 provider 配置 id |
| `--model` | 可选，须与 `--provider` 同时给出 | `provider models` 中的模型 id |
| `--permission` | 可选 | 该 Agent 的权限模式 id。Id 见 [Agent](/zh-cn/docs/agents/#权限模式) |
| `--title` | 可选 | 会话标题。省略时标题为该 Agent 的名称 |
| `--role` | 可选 | 已保存的 [Agent 角色](/zh-cn/docs/agents/#agent-角色)。它提供 Agent、模型和权限 |

`session runtime` 打印会话正在使用的模型和运行时选项。`session configure` 在该会话上修改它们。某个 flag 取 `default` 会把这一项恢复成 Agent 自己的默认值。`--fast` 为 `on`、`off` 或 `default`。

Daemon 会补上你省掉的项。省略 `--agent` 时，用该工作区最近更新的会话所用的 Agent。那个 Agent 当前不可用，或这个工作区还没有会话时，用这台电脑上第一个可用的 Agent。省略 `--permission` 时，用该工作区里这个 Agent 最近一次会话的权限模式（该模型仍允许这个模式时）；否则用该模型允许的第一个模式。没有权限模式的 Agent（例如 Pi）不会设置模式。同时省略 `--provider` 和 `--model` 时，模型依次是：该 Agent 的默认模型、这个 Agent 在该工作区上次使用的模型、第一个兼容模型。这个 Agent 没有兼容模型时，会话仍会创建，只是不设置模型。像以前一样同时传入 `--agent`、`--provider` 和 `--model` 的命令仍然有效。

`--provider` 和 `--model` 必须一起给出。只给其中一个会失败，并提示 `--provider and --model must be given together`。这台电脑上不可用的 Agent 会提示 `<agent> is not available on this machine`。省略 `--agent` 且没有可用 Agent 时，提示是 `No agent is available on this machine`。Agent 不能使用的模型会提示 `<provider>/<model> is not available for <agent>`。该 Agent 不提供的模式会提示 `<mode> is not a permission mode of <agent>`。

不带 flags 的 `session tui` 附着到最近的非归档会话。传入 `--workspace`、`--agent`、`--provider` 或 `--model` 时，它会按与 `session create` 相同的默认值创建会话——这次创建仍然需要 `--workspace`——然后附着。`--permission` 和 `--title` 在创建时生效。它不支持 `--json`。

`session tree` 打印[执行树](/zh-cn/docs/desktop/#执行树)。`fork` 从当前会话开一个新会话（`--through` 截到该消息）。`switch-agent` 在空闲会话上更换运行时。`handoffs` 列出分叉或切换 Agent 后的上下文交接。见[分叉与切换 Agent](/zh-cn/docs/desktop/#分叉与切换-agent)。

`peers` 列出某会话可以发消息的会话；`send-peer` 把消息作为新一轮投递（或排在当前一轮之后）；`peer-inbound refuse` 让会话拒收其他会话的消息。见[会话间消息](/zh-cn/docs/teams/#会话间消息)。

Agent id 与权限见 [Agent](/zh-cn/docs/agents/)。

## 团队

一个主会话及其队友。完整模型见 [Agent 团队](/zh-cn/docs/teams/#agent-团队)。

```bash
cocurdex team get --lead <session-id> [--json]
cocurdex team create --lead <session-id> --template <template-id>
cocurdex team spawn --lead <session-id> --name <name> [--title <title>] --prompt <prompt> [--role <role-id>] [--agent <agent>] [--worktree]
cocurdex team stop --team <team-id>
cocurdex team stop-member --team <team-id> --session <session-id>
cocurdex team roles [--json]
cocurdex team templates [--json]
cocurdex team spawn-template --lead <session-id> --template <template-id> [--prompt <prompt>]
```

| Flag | 含义 |
| --- | --- |
| `--lead` | 拥有该团队的主会话 |
| `--name` | 队友名称，小写 slug |
| `--title` | 应用中显示的标题；不填则显示名称 |
| `--role` | 队友使用的已保存 Agent 角色 |
| `--agent` | 不使用角色时的 Agent id，默认与主会话相同 |
| `--worktree` | 让队友运行在独立的托管 git 工作树中 |

## 脚本编排

经批准后分发给子 Agent 的 JavaScript 扇出。完整模型见[脚本编排](/zh-cn/docs/teams/#脚本编排)。

```bash
cocurdex script-run list [--session <requester-session-id>] [--workspace <workspace-id>] [--json]
cocurdex script-run get --run <run-id> [--json]
cocurdex script-run create --session <requester-session-id> --name <name> --file <script.js>
cocurdex script-run start --run <run-id> [--max-agents <n>]
cocurdex script-run cancel --run <run-id>
```

`create` 创建一个归属于发起会话的 `draft` 运行；`start` 批准并以给定的 Agent 上限（正整数）运行。结果会送回发起会话。

## Provider

Provider 配置为内置 Pi Agent 和共享模型目录提供数据。见 [Provider 与设置](/zh-cn/docs/providers-and-settings/#provider-与模型)。

```bash
cocurdex provider list [--json]
cocurdex provider templates [--json]
cocurdex provider add <id> [--template <template-id>] [--name <name>] [--base-url <url>]
cocurdex provider update <id> [--name <name>] [--base-url <url>] [--enable|--disable]
cocurdex provider remove <id>
cocurdex provider status <id> [--json]
cocurdex provider login <id> [--method oauth|api_key] [--no-tui]
cocurdex provider logout <id>
cocurdex provider key set <id>        # 从 stdin(或隐藏输入提示)读取密钥
cocurdex provider key clear <id>
cocurdex provider models <id> [--refresh] [--json]
cocurdex provider model add <id> <model-id> --api <api> [--name <name>]
cocurdex provider model remove <id> <model-id>
cocurdex provider default [--agent <agent>] [--provider <id> --model <model-id>] [--json]
cocurdex provider import <file|->     # pi models.json 格式
cocurdex provider export [--output <file>]
```

| 命令 | 说明 |
| --- | --- |
| `add` | 需要 `--base-url`，或 `provider templates` 中的某个 `--template` |
| `login` | 默认 `--method oauth`;stdin 和 stdout 都是终端时使用终端 UI,`--no-tui` 则用纯文本 |
| `models --refresh` | 从 provider 拉取最新目录，而不是读取已保存的列表 |
| `model add --api` | 取值为 `openai-completions`、`openai-responses`、`openai-codex-responses`、`anthropic-messages`、`google-generative-ai`、`mistral-conversations` 之一 |
| `default` | 不带参数时列出每个 Agent 的默认 provider 与模型；带 `--agent --provider --model` 时设置默认值 |
| `model set` | 修改一个模型的参数。内置目录里的模型会保留你没有改过的字段。`--context` 和 `--output` 接受 token 数或 `none` |
| `model reset` | 丢掉这些修改，恢复目录里的值。在你重置之前，设置里该模型一行会标为**已修改** |

```bash
cocurdex provider model set <id> <model-id> [--enable|--disable] [--api <api>] [--context <tokens>|none] [--output <tokens>|none] [--capabilities <a,b>] [--reasoning on|off]
cocurdex provider model reset <id> <model-id>
```

## MCP 服务器

Cocurdex 提供给 Agent 的服务器。桌面入口是 [MCP 服务器](/zh-cn/docs/providers-and-settings/#mcp-服务器)。

```bash
cocurdex mcp list [--workspace <id|path>] [--json]
cocurdex mcp show [<name>]
cocurdex mcp add <name> [--env KEY=VALUE]... [--cwd <dir>] [--description <text>] [--disabled] [--agent <id>]... -- <command> [args...]
cocurdex mcp add <name> --url <url> [--header KEY=VALUE]... [--bearer-token-env-var <NAME>] [--description <text>] [--disabled] [--agent <id>]...
cocurdex mcp remove <name>
cocurdex mcp enable|disable <name>
cocurdex mcp agents <name> [<agent>...|--none] [--json]
cocurdex mcp test <name> [--workspace <id|path>] [--json]
cocurdex mcp login <name> [--workspace <id|path>]
cocurdex mcp logout <name> [--workspace <id|path>]
cocurdex mcp import <file|-> [--overwrite]
cocurdex mcp import --from claude|claude-project|codex|codex-project|cursor|opencode|opencode-project|antigravity [--name <name>]... [--overwrite] [--workspace <id|path>]
```

`--agent` 可以重复。`agents <name> --none` 清空 Agent 列表。`import --from` 读取这台电脑上该 Agent 已经有的服务器；重复 `--name` 则只导入这些服务器。在**应用**里管理的 Notion、Linear 或 GitHub 连接，不在这里分配给 Agent。对它执行 `mcp agents` 会失败，提示 `Manage assistant access with cocurdex apps update.`

## 应用

给助理使用的 Notion、Linear 和 GitHub 账号。桌面入口是[应用](/zh-cn/docs/assistants/#应用)。这些命令打印 JSON。`login-cancel` 只停止这次授权，不打印内容。

```bash
cocurdex apps catalog|list [--json]
cocurdex apps add <notion|linear|github> --name <name> [--assistants <id,id>] [--delegated] [--work-sessions true|false] [--json]
cocurdex apps update --stdin [--json]
cocurdex apps check|tools|logout|remove <connection-id> [--json]
cocurdex apps login <connection-id> [--json]
cocurdex apps login-wait|login-cancel <connection-id> --login <id> [--json]
cocurdex apps login-return <connection-id> --login <id> --stdin [--json]
cocurdex apps read|call <connection-id> --tool <name> --stdin [--json]
```

| 命令 | 说明 |
| --- | --- |
| `catalog` | 打印 Notion、Linear 和 GitHub。不需要正在运行的 daemon |
| `add` | `--name` 必填。`--assistants` 是用逗号分开的助理 id。`--delegated` 允许委派的工作会话和队友使用这个账号。`--work-sessions true` 或 `false` 设置**工作模式可用**；省略则这条连接可以在工作模式里使用。未知 id 失败并提示 `Choose notion, linear, or github`。`--work-sessions` 写成别的值会失败，提示 `--work-sessions takes true or false` |
| `update` | 从标准输入读一个 JSON 对象。字段：`id`、`revision`、`displayName`、`personaIds`、`allowDelegatedWork`、`allowWorkSessions`、`enabled`。把这段 JSON 写在命令参数里会失败，提示 `Pass the update JSON through --stdin; never put credentials in command arguments.` `revision` 过期会失败，提示 `Application changed. Reload before saving.` |
| `check` / `tools` / `logout` / `remove` | 一个连接 id。`remove` 打印 `{ "removed": true }` |
| `login` | 开始授权，并打印这次登录，包括它的 id。GitHub 在有 `gh` 登录时用它，否则使用设备码 |
| `login-wait` / `login-cancel` | `--login` 是那个登录 id |
| `login-return` | 完整的回调地址是标准输入的文本，不是参数。没有标准输入时失败，提示 `Pass the complete return URL through --stdin`。GitHub 的设备码登录会失败，提示 `GitHub authorization finishes in the browser` |
| `read` / `call` | `--tool` 是工具名。参数是标准输入上的一个 JSON 对象。`read` 只限提供方声明为只读的工具 |

## 诊断

```bash
cocurdex daemon status [--json]
cocurdex daemon health [--json]
cocurdex daemon background on|off|status [--json]
cocurdex diagnostics export [--json]
cocurdex diagnostics level debug|info [--json]
```

`daemon health` 打印进程、内存、正在进行的工作，以及日志位置。`daemon background` 用来打开或关闭**后台常驻**，或打印当前状态。见 [Daemon 与工作区](#daemon-与工作区)。`diagnostics export` 写出和 **设置 → 诊断** 相同的已脱敏打包文件。`diagnostics level` 对应**详细诊断日志**：`debug` 记录更多，`info` 是平常级别。见[诊断](/zh-cn/docs/providers-and-settings/#诊断)。

## Agent 角色

保存好的 Agent 预设（Agent + provider/模型 + 权限 + 推理轴、头像、描述），可用于会话、队友或脚本编排的子 Agent。在桌面 UI 中管理；从 CLI 列出：

```bash
cocurdex role list [--json]
```

## CLI 不是什么

- 第二份事实源——本地数据库仍由桌面 daemon 掌管
- 多面板桌面工作台的完整替代品
- 云端团队管理工具（那会是独立的 console + API）
- 打开 `cocurdex.sqlite` 或私有 schema 路径的许可证

## 安全

不要把脚本指向 `cocurdex.sqlite` 或私有 schema 路径。它们是实现细节，预发布期间可能在没有兼容性承诺的情况下变化。优先使用 `--json` 输出和 CLI 返回的稳定 id。
