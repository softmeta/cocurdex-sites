Cocurdex 在一个工作区里协调**多个 Agent 会话**。预发布期间运行时和 provider 仍在演进；本页描述产品模型和当前可用的 Agent。

## 心智模型

- 每个会话都有明确的**状态**和推导出的**注意力**状态（见[桌面工作台](/zh-cn/docs/desktop/)）。
- 你可以运行**多个**会话，而不必合并成一条对话记录。
- 权限、提问和计划批准会浮现在 UI 中，而不是静默发生。
- 优先选择仍能完成任务的最**窄**权限和写入模式。

## 支持的 Agent

| Id(`--agent`) | UI 名称 | 运行时 | 说明 |
| --- | --- | --- | --- |
| `claude-agent` | Claude Agent | 外部 `claude` CLI | 计划模式、引导、本地写入 |
| `codex` | Codex | 外部 `codex` CLI | 计划模式、引导、本地写入；授权经由 Codex 自身 |
| `cursor` | Cursor | 外部 `cursor-agent acp`（ACP） | 流式输出、本地写入；无计划模式与引导；通过 Cursor 登录 |
| `devin` | Devin | 外部 `devin acp`（ACP） | 流式输出、本地写入；无计划模式与引导；通过 Devin 登录 |
| `grok-build` | Grok Build | 外部 `grok` CLI（ACP 传输） | 计划模式、经 ACP 引导；仅本地写入 |
| `opencode` | OpenCode | 外部 `opencode` CLI | 计划模式、流式输出；不支持引导 |
| `pi` | Pi | 内置 | 使用你的 [Provider 配置](/zh-cn/docs/providers-and-settings/)和 [MCP 服务器](/zh-cn/docs/providers-and-settings/#mcp-服务器)；只读写入模式 |

外部 Agent 必须在你的机器上安装并完成授权。缺少某个 CLI 时，该 Agent 会显示为不可用，直到你安装它——**设置 → 适配器** 会显示探测结果以及其余 Agent 的安装方法。

**ACP** Agent（Cursor、Devin、Grok Build）使用 [Agent Client Protocol](https://agentclientprotocol.com)。Cocurdex 从 Agent 自身读取模型目录和会话模式，因此你看到的选项会跟随已安装 CLI 的版本。

### 如何选择运行时

| 场景 | 从这些开始 |
| --- | --- |
| 你已经在用 Claude Code / Claude CLI | `claude-agent` |
| 你已经在用 OpenAI Codex | `codex` |
| 你想要偏 Grok 的实现 | `grok-build` |
| 你在别处使用 OpenCode | `opencode` |
| 你有 Cursor 订阅 | `cursor` |
| 你在用 Devin | `devin` |
| 不需要本地工作区写入的轻量对话轮次 | `pi`(Pi) |

## Provider 与模型

Agent 使用应用中注册的 **provider 配置**（API base URL、凭据、目录）和**模型**。在桌面 UI 中配置 provider;从 CLI 列出：

```bash
cocurdex provider list
cocurdex provider models <provider-id>
```

Cocurdex 会尽可能复用你已有的 provider 配置(例如 `~/.codex` 下的 Codex 账户状态)。不要把密钥贴进产品笔记或公开文档站。

## 权限模式

权限模式**因 Agent 而异**。风险等级：

| 风险 | 意图 |
| --- | --- |
| **normal** | 询问或谨慎门控工具使用 |
| **elevated** | 更宽松地自动批准编辑 / 评审 |
| **dangerous** | 完全或绕过式访问——谨慎使用 |

### Claude Agent

| 模式 id | 风险 |
| --- | --- |
| `claude-default` | normal |
| `claude-accept-edits` | elevated |
| `claude-auto` | elevated——当安装的 Claude CLI 支持 auto 模式时提供；Haiku 模型不可用 |
| `claude-bypass-permissions` | dangerous |

当协作模式为 `plan` 时，会话使用 `claude-plan`（只做计划，不编辑也不执行命令）。切回 `default` 会恢复为 `claude-default`。

### Codex

| 模式 id | 风险 |
| --- | --- |
| `codex-read-only` | normal |
| `codex-auto` | elevated |
| `codex-full-access` | dangerous |

### Grok Build

| 模式 id | 风险 |
| --- | --- |
| `grok-ask` | normal |
| `grok-auto` | elevated（Grok 自己的风险分类器；可能产生额外的模型调用） |
| `grok-always-approve` | dangerous |

### OpenCode

| 模式 id | 风险 |
| --- | --- |
| `opencode-ask` | normal |
| `opencode-allow` | elevated |
| `opencode-deny` | normal |

### Cursor 与 Devin

Cocurdex 侧没有独立的权限模式列表。工具审批遵循 Agent 自身的 ACP 权限请求，和其他 Agent 一样以权限卡片呈现。

### 内置 Pi(`pi`)

没有独立的权限模式列表；写入模式为 **read-only**。

当 Agent 请求特权操作时，Cocurdex 会浮现一张权限卡片（可能附带路径/操作细节）。在会话 UI 或 CLI 的 `session tui` 中处理。

## 协作与写入模式

| 控制项 | 取值 | 含义 |
| --- | --- | --- |
| **协作模式** | `default`、`plan` | 运行时支持计划优先循环时的计划模式 |
| **写入模式** | `read-only`、`native-write` | 工具是否可以修改工作区 |

不是每个 Agent 都支持每种组合。例如 Grok Build 专注于本地写入；内置 `pi` 偏只读。

## Agent 角色

**Agent 角色**是保存好的预设：Agent + provider/模型 + 权限模式 + 协作与推理轴，外加可选的指令和 skills。在 **设置 → 角色** 中管理角色（或从会话 UI 把当前会话配置保存为角色），并从 CLI 列出：

```bash
cocurdex role list
```

新建会话时可以直接套用角色，也可以把角色分配给[队友](/zh-cn/docs/teams/#agent-团队)或[脚本编排的子 Agent](/zh-cn/docs/teams/#脚本编排)。

## Cocurdex Agent 工具

daemon 为每个会话挂载一个本地 MCP 工具服务。工具按组划分，只在合适的场景提供：

| 分组 | 工具 | 提供给 |
| --- | --- | --- |
| `team` | `spawn_teammate`、`spawn_template`、`list_roles`、`list_templates`、`stop_member`、`stop` | 主会话（团队 lead） |
| `team` | `task_create`、`task_list`、`task_update` | 主会话与队友 |
| `messaging` | `list_agents`、`send_message` | 主会话与队友 |
| `script_run` | `propose` | 主会话 |
| `settings` | `list`、`get`、`set`、`propose` | 主会话（也驱动[设置助手](/zh-cn/docs/providers-and-settings/#设置助手)） |

脚本编排启动的子 Agent 不获得以上任何工具。具体用法见[团队与编排](/zh-cn/docs/teams/)。

## 会话内控制

一些运行时可以在**不重建** provider 会话的情况下切换**模型**、**思考/推理力度**、**权限**或相关轴。这能保持对话连续性和 provider 侧的缓存。如果某个 Agent 缺少某个控制项，那是有意不支持——没有「暗中重启会话」的兜底。

## 引导与后续输入

当 Agent 支持**引导**(steering)时，你可以在运行进行中发送后续指引（或把后续输入排队到当前轮次结束——可在对话设置中配置）。当引导不可用时，等待当前轮次结束或停止会话。

从 UI 或以下命令停止运行中的会话：

```bash
cocurdex session stop <session-id>
```

## 并行会话

典型模式：

1. 一个会话实现功能
2. 一个会话排查 bug 或评审分支
3. 可选的计划模式会话做设计

标题保持简短，状态保持可见。只在有注意力需求时切换——不要为了「省一个会话位」把不相关的工作塞进同一条对话记录。
