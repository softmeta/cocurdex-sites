**助理**是桌面侧边栏里的一种表单，与**工作**和**聊天**并列。每个助理是一份保存在内置 **Pi** Agent 上的角色（名称、模型、指令、头像），外加一条长期的主线程。应用始终保留一个默认助理，在你改名之前它叫**助理**。

从侧边栏的切换器打开这个表单。没有选中其他内容时，它会打开默认助理，输入框已经在那里。

## 列表

**助理**列表显示每个助理的最新回复；主线程正在运行时显示**正在处理…**。默认助理始终排在最前。**置顶**让其他助理留在未置顶的那些之上。

右键一行：

| 操作 | 作用 |
| --- | --- |
| **编辑** | 打开**编辑助理**，修改名称、**模型**、**指令**、**人设**、描述和头像。没有引擎选择器 |
| **置顶** / **取消置顶** | 把这个助理留在未置顶的那些之上。默认助理不提供这项 |
| **免打扰** / **取消免打扰** | 隐藏这一行的未读标记。免打扰的一行会显示**免打扰**。免打扰的助理不会向桌面或手机发提醒；它的线程仍会出现在收件箱 |
| **标为未读** | 把主线程最近一次结果标为未读。这个助理不是当前打开的，并且那次结果已经读过时才提供 |
| **复制** | 复制这个助理，名称后加上**副本**，并打开副本 |
| **删除** | 删除这个助理、它的主线程和例行任务（包括每一次运行的线程）。记忆保留。每个助理都提供，包括默认助理 |

切换器那一行上的**新建助理**（撰写按钮）沿用默认助理的模型，然后打开**编辑助理**。

助理的角色和主线程不能单独删除或归档。在 **设置 → 角色** 里删除这个角色会失败，提示 `Delete the personal agent instead of its role`。删除或归档主线程会失败，提示 `A personal agent's home thread cannot be removed`。删除默认助理时，列表里的下一个成为默认助理，并取消它的置顶。一个都不剩时，下次打开**助理**，应用会新建一个名为**助理**的默认助理。`cocurdex persona delete` 同样如此，包括默认助理。

助理只在 Pi 上运行。创建、更新或保存角色时如果指定了别的 Agent，会失败，提示 `Personal agents run on pi, not <agent>`。原来用其他 Agent 的助理，连同主线程和例行任务线程，都会改到 Pi。Pi 已经提供这个模型时，模型保持不变；否则改用 Pi 的默认模型。

在**编辑助理**里更换模型时，主线程和这个助理当前的例行任务线程也会改用新模型。已归档的运行线程保持原样。

头像可以是 emoji，也可以是形状。选择器里有**形状**、**表情**（**平静**、**开心**、**眨眼**、**困倦**、**好奇**）和**颜色**。没有头像的角色会得到自己的形状、表情和颜色。在这份列表里，形状看着右上方，跟着指针在这一行上移动，悬停时会眨眼。线程标题上的头像保持不动。

在助理线程里，你的消息气泡会带上这个头像颜色的一层浅色。其他消息保持中性。

## 主线程

助理线程使用聊天布局：空线程中央是名称和头像，输入框停在底部。占位是**给**这个助理的名字**发消息**。还没写描述时，空线程写着**你的私人助理，记得你，替你盯着每天的事。** 三条建议会填进输入框：

- **今天有什么需要我关注的？**
- **每天早上 8 点给我一份简报**
- **你记得关于我的哪些事？**

窗格标题显示助理的头像。这些线程不会出现在**工作**的会话列表里。

一轮进行中时，线程显示助理头像和**思考中**；正在使用工具时是**正在处理**。它不显示工作模式的计时，也不逐步展开每次工具调用。输入框不提供 Agent、模型或用量控件。在**编辑助理**里，模型这一栏的标签是**模型**。

**指令**说明这个助理负责什么、应该怎么做事。**人设**是它对你是谁：语气、性格，以及和你说话的方式（最多 20,000 个字符）。在**编辑助理**里填写，或用 CLI 的 `--instructions` / `--instructions-file` 和 `--soul` / `--soul-file`。两者每一轮都会作为系统提示里的一节带上，所以修改从下一条消息起生效。保存时如果没有带上指令或 skills，已经存下的内容会保留，包括用 CLI 设过的指令。

应用贴进主线程的消息会带一行来源。**今日简报**是每日简报。**来自例行任务**加上任务名称，是一次例行任务的结果；点它打开那次运行的线程。委派出去的会话在完成、失败、取消或中断后，也会同样贴回主线程，助理再接一轮告诉你发生了什么。见[委派工作](#委派工作)。

## 概览

打开一个助理时，右侧面板是**助理概览**。助理和工作各自记住上一次打开的视图。**Git** 和**终端**留在工作表单里，助理的切换器里没有它们。没有选中助理时，面板写着**选择助理以查看其工作**。

顶栏是助理的头像、名称和描述。还没写描述时，这里写着**协调工作、保留上下文并跟进结果。**

| 区块 | 显示 |
| --- | --- |
| **需要你处理** | 这个助理、它委派的工作或它的例行任务里，需要你处理或已经失败的收件箱项。有内容时才出现。点一行会打开那个会话，或选中对应的例行任务 |
| **委派工作** | 这个助理交出去、并且正在运行或空闲的会话。一行显示工作区、Agent，以及**执行中**或**空闲**。点它打开原来的工作会话。没有内容时写着**此助理委派的工作会显示在这里。** 会话已经不在时提示**这个工作会话已不可用。** |
| **最近结果** | 同一批会话在不再执行、也不再空闲之后：**本轮已完成**、**失败**、**已取消**、**已中断**或**已归档**。有内容时才出现 |
| **例行任务** | 这个助理自己的例行任务。一行显示下次运行时间和时区，或者**已暂停**、**因连续失败已暂停**、**暂无下次运行时间**。点一条会选中它并打开**例行任务**。**管理此助理的例行任务**打开列表，不预选任何一条。这一段写着**由当前连接的主机执行，需要其后台服务在线。** |
| **上下文与资料** | **记忆**、**笔记**、**事项**和**会话文件** |
| **应用** | **连接应用**。说明是**连接账号，设置助理使用权限，并查看可用工具。** |

某一份列表加载失败时，对应位置会提供**工作加载失败，重试**、**例行任务加载失败，重试**或**助理加载失败，重试**。

**会话文件**列出本次会话的附件和打开过的文件。标题下写着**本次会话的附件和已打开文件**。没有文件时是**暂无会话文件**。图片会打开预览。PDF 会在 [PDF 阅读器](/zh-cn/docs/desktop/#pdf-阅读器)里打开，包括上传到这次会话里的 PDF。其他文件在编辑器里打开。助理面板的**更多视图**里还有**浏览器**和**演示文稿**。有 PDF 打开时，切换器里会出现 **PDF**。

## 委派工作

个人助理自己不改仓库。它把这件事交给你某个工作区里的普通工作会话。会话使用这个工作区最近用过的 Agent 和模型，或一份已保存的 [Agent 角色](/zh-cn/docs/agents/#agent-角色)，或带领一份已保存的[团队模板](/zh-cn/docs/teams/#团队模板)。也可以在一棵新的[工作树](/zh-cn/docs/desktop/#工作树)里运行。会话出现在**工作**里，你可以跟进，也可以自己接手。

任务进到那个会话时，会标明来自这个助理。会话每完成一轮，或者这一轮失败、被取消、被中断，结果都会贴回主线程，助理再告诉你发生了什么。你可以从概览打开原来的会话，也可以从那条消息打开。需要批准和提问的事项进[收件箱](#收件箱与今日简报)，不经过助理。助理只能列出、发消息和停止它自己委派的会话。

可以直接让助理做这件事。工具是 `work_catalog`、`work_start`、`work_list`、`work_send` 和 `work_stop`。`work_catalog` 列出工作区（不包括聊天，也不包括助理自己的工作区）、已保存的 Agent 角色和团队模板。角色和团队模板二选一。都不填时，会话使用这个工作区最近用过的 Agent 和模型。团队模板让这个会话带领那份模板，并用模板里的第一名成员作为它自己的角色。后续消息在这个 Agent 支持插入时会进入当前这一轮，否则等到这一轮结束。例行任务只有在**完全权限**下才能委派。同样的操作是 `cocurdex persona work`。见 [CLI](#cli)。

## 应用

右侧面板的**应用**在这台电脑上连接 Notion、Linear 和 GitHub，再选择哪些助理可以使用每个账号。自定义 MCP 服务器仍在 **设置 → MCP**。顶栏的**自定义 MCP** 打开那一页。添加连接不等于完成授权。页面写着**凭据保存在当前主机。账号和工作空间的访问范围由应用的授权页面控制。添加连接不等于完成授权。**

**搜索应用**同时筛选两份列表。没有匹配时显示**没有匹配的连接**。

**已添加的连接**显示每条连接的名称、`notion`、`linear` 或 `github`、可以使用它的助理数量，以及状态：

| 状态 | 何时 |
| --- | --- |
| **已停用** | **启用**关闭 |
| **需要配置** | GitHub 连接还没配好它的 OAuth 应用 |
| **尚未检查** | 还没检查过 |
| **已连接** | 最近一次检查成功 |
| **需要授权** | 账号还需要授权 |
| **连接失败** | 最近一次检查失败 |

**可连接的应用**：

| 应用 | 如何授权 |
| --- | --- |
| **Notion** | **在浏览器中授权** |
| **Linear** | **在浏览器中授权** |
| **GitHub** | **需要配置自有 OAuth 应用** |

**添加**会按应用的名字建一条连接。如果当前开着一个助理，这个助理会得到使用权限。**允许委派工作使用**一开始是关的。

| 控件 | 作用 |
| --- | --- |
| **连接名称** | 列表里的名字。它不是账号本身。账号和工作空间由应用的授权页面决定 |
| **启用** | 打开或关闭这条连接 |
| **助理使用权限** | 每个助理一个开关。**仅选中的助理可以使用此连接。连接前请先保存修改。** |
| **允许委派工作使用** | **这些助理委派的工作会话和队友也可以使用此账号，其他工作会话无法使用。** |
| **保存权限** | 保存名称、开关，以及 GitHub 凭据 |
| **授权连接** | 开始授权。连接必须是启用的；GitHub 还要先完成配置 |
| **检查连接** | 检查这条连接，并把结果和检查时间显示在一起 |
| **查看工具** | 列出**可用工具**和每个工具的说明 |
| **退出授权** | 在这台电脑上退出这条连接 |
| **查看应用说明** | 打开这个应用自己的文档 |
| **移除连接** | 去掉这台电脑上的连接和已保存的授权。确认框写着**移除此主机上的连接及其已保存的授权？应用账号设置中可能仍需单独撤销授权。** |

授权进行中时，页面先显示**正在准备授权…**，然后是**等待授权完成**，并提供**打开授权页面**。在另一台设备上授权时，把浏览器里完整的 localhost 回调地址粘贴到**授权回调地址**，再选**完成授权**。页面写着**此地址包含敏感信息，请勿发送到聊天中。** **取消**会停掉这次授权。

连接在别处已经改过再保存，会失败并提示 `Application changed. Reload before saving.`

**GitHub OAuth 应用**只出现在 GitHub 连接上。注册一个属于你自己的 OAuth 应用。**注册 OAuth 应用**打开 GitHub 的开发者设置。使用页面上显示的回调地址 `http://127.0.0.1:<port>/callback`，并填写**客户端 ID**和**客户端密钥（留空保留现有密钥）**。**回调端口**接受 1024 到 65535，一开始是 `19173`。其他值会失败，提示**请选择 1024 到 65535 之间的回调端口**。保存后不会再次展示密钥。还没填完就检查或授权，会失败并提示 `Register your GitHub OAuth app and configure its client ID and callback port first.` 或 `Configure your GitHub OAuth app first.`

连接已启用、并且选中了这个助理时，助理才能使用它。委派出去的工作会话或队友还需要打开**允许委派工作使用**。否则调用失败，提示 `This assistant is not allowed to use this application`。已停用的连接失败并提示 `Application is disabled`。

**只读加草稿**的例行任务只能调用提供方声明为只读的工具。其他工具会失败，提示 `This tool is not declared read-only. Describe the action for the user instead.` **完全权限**可以调用其余工具。一次写入的结果不清楚时，先看远端的实际状态，再决定要不要重试。

还没有授权时，助理会请你打开**应用**，而不会让你把凭据贴进对话。工具是 `applications_list`、`applications_tools`、`applications_read` 和 `applications_call`。`applications_read` 是只读调用。`applications_call` 是一般调用。

列在 **设置 → MCP** 里的这类连接会写明**此连接由「应用」管理。请在那里选择助理使用权限，不使用按引擎分配 MCP 的方式。** 对它执行 `cocurdex mcp agents` 会失败，提示 `Manage assistant access with cocurdex apps update.` 同样的操作是 `cocurdex apps`。见 [CLI](#cli)。

## 例行任务

右侧面板的**例行任务**给助理安排定时工作。每次运行都新开一条 Pi 线程，上一次运行的线程会被归档。列表可以用**全部助理**或某一个助理筛选。

| 字段 | 作用 |
| --- | --- |
| **助理** | 由哪个助理运行 |
| **名称** | 列表里和来源行上的名字 |
| **指令** | 每次运行要做的事。每次运行只从这段文字开始 |
| **时间安排** | **间隔**为每 N 分钟（至少 5 分钟），或**定时**（24 小时制的 `HH:MM`）。**重复日**选择星期几；全部选中就是每天 |
| **时区** | 这个任务使用的时区。新建时填这台电脑的时区 |
| **权限** | 这次运行可以做多少（见下） |
| **通知** | 结果送到哪里（见下） |

**权限**默认是**只读加草稿**。选项是**只读加草稿**和**完全权限**。**先问我**已取消：以前用它的任务现在是**只读加草稿**。

| 权限 | 含义 |
| --- | --- |
| **只读加草稿** | 只能读取和起草，不会发送或修改任何东西。这次运行可以使用 `read`、`grep`、`find`、`ls`、记忆和历史、例行任务工具，以及已允许的应用里由提供方声明为只读的工具（`applications_list`、`applications_tools`、`applications_read`）。其他工具会被拦住，包括嵌套在另一个工具里的写入、会修改数据的应用工具，以及委派工作 |
| **完全权限** | 无人值守，拥有全部权限 |

**通知**默认是**收件箱**。

| 通知 | 含义 |
| --- | --- |
| **收件箱** | 结果进收件箱，失败时通知你 |
| **推送** | 每次有结果都推送到手机 |
| **静默** | 只记录运行 |

每次运行结束时调用一次 `routine_report`，状态是 `ready`、`dropped`、`needs_you`、`blocked` 或 `failed`。如果运行完成时没有报告，最后一条回复就是结果。**最近运行**显示下面的标签；有摘要或问题时一并显示。

| 报告 | 在**最近运行**里 | 你会看到 |
| --- | --- | --- |
| `ready` | **成功** | 除非**通知**是**静默**，否则贴进主线程。只有**通知**是**推送**时才提醒 |
| `dropped` | **无可汇报** | 只记录。不会贴进主线程或收件箱，也不会提醒 |
| `needs_you` | **需要你处理** | 贴进主线程，并在收件箱里标为**需要你处理**，**通知**是**静默**时也一样。提醒一次，作为提问 |
| `blocked` | **受阻** | 与**需要你处理**相同 |
| `failed` | **失败** | 计入连续三次失败后的暂停。**通知**是**收件箱**或**推送**时会提醒 |

贴进去的结果标为**来自例行任务**加上任务名称。点这一行打开那次运行的线程。免打扰的助理不会提醒。

**打开线程**打开最近一次运行的线程。**立即运行**开始一次运行。**暂停**和**恢复**由你手动操作。连续三次运行失败后，任务会自己暂停：**连续三次运行失败，已自动暂停。排除原因后再恢复。** 电脑睡眠期间错过的运行，会在电脑醒来后补跑一次，而不是每个错过的间隔都补一次。每个例行任务一天最多运行 24 次；超出的运行记为**已跳过**，并提示 `The daily run limit was reached.` 一次运行在 20 分钟后停止，提示 `The run hit its 20-minute limit and was stopped.` 被重启打断的运行记为失败，提示 `The daemon stopped during the run.` 任务等到下一个档期，不会重放这次运行。

**删除**会去掉例行任务和每一次运行的线程。确认框写着**例行任务和它的线程都会被删除，无法撤销。**

你也可以让助理管理它自己的例行任务。它不能授予**完全权限**，也不能修改或运行已经是完全权限的任务。同样的操作是 `routine_list`、`routine_create`、`routine_update`、`routine_run`、`routine_runs`、`routine_delete` 这些工具。`routine_report` 只在一次运行进行中可用。委派工作和使用应用是另外两组工具，见[委派工作](#委派工作)和[应用](#应用)。也可以用 [CLI](#cli)。

## 收件箱与今日简报

**收件箱**在名单下面。它是所有表单共用的一份列表：需要你处理的权限、提问和计划，已完成和失败的会话，以及例行任务的结果、需要你处理的运行、失败和暂停。

| 类型 | 标签 |
| --- | --- |
| 审批 | **等你审批** |
| 提问 | **有问题要问你** |
| 计划 | **计划待确认** |
| 已完成的会话 | **已完成** |
| 失败的会话 | **失败了** |
| 例行任务结果 | **有新结果** |
| 例行任务需要你 | **需要你处理** |
| 例行任务失败 | **例行任务失败** |
| 例行任务暂停 | **连续失败已暂停** |

标题会带上数量，例如**收件箱 · 3**。打开一项时，侧边栏留在**助理**，并打开那个会话。在手机上，需要你处理或受阻的例行任务使用同一个**需要你处理**标签。

每日简报不再是对话框。应用按你的语言来写。切换器那一行上的**今日简报**会在你回来时把最新简报贴进默认助理的主线程，并打开那条线程。这条消息是普通回复，标为**今日简报**，里面有**需要你处理**、**例行任务结果**和**失败**。没有变化时，再次发布会跳过。没有可报告的内容时，这个按钮不显示。静默例行任务的结果不会出现在**例行任务结果**里。需要你处理的运行仍会出现在**需要你处理**下面。

## CLI

`<persona>` 或 `<routine>` 参数可以是 id、唯一的 id 前缀，或名称（不区分大小写）。个人助理始终跑在 Pi 上。完整参考见 [CLI](/zh-cn/docs/cli/#助理)。

```bash
cocurdex persona list
cocurdex persona show <persona>
cocurdex persona create --name <name> [--provider <id> --model <id>] [--description <text>] [--instructions <text>|--instructions-file <path>] [--soul <text>|--soul-file <path>]
cocurdex persona update <persona> [--name <name>] [--provider <id> --model <id>] [--description <text>] [--instructions <text>|--instructions-file <path>] [--soul <text>|--soul-file <path>] [--pin|--unpin] [--mute|--unmute]
cocurdex persona duplicate <persona> --name <name>
cocurdex persona delete <persona>
cocurdex persona send <persona> <message> [--wait] [--timeout <seconds>]
cocurdex persona thread <persona> [--limit <n>]
cocurdex persona work catalog [--json]
cocurdex persona work list <persona> [--json]
cocurdex persona work start <persona> --workspace <id|name> --prompt <text>|--prompt-file <path> [--title <title>] [--role <role>|--team <template>] [--worktree] [--json]
cocurdex persona work send <persona> <session-id> <message> [--json]
cocurdex persona work stop <persona> <session-id> [--json]
```

`--provider` 和 `--model` 要一起给出。没有 `--agent` 参数。`persona send` 发到主线程。`--wait` 在这一轮结束时打印回复（默认等待 600 秒）。`persona thread` 打印最近的消息（默认 20 条）。`--mute` 停止这个助理的桌面和手机提醒。

`persona work catalog` 列出工作区、已保存的 Agent 角色和团队模板。`list` 打印 `sessionId`、`title`、`workspaceName`、`agentType` 和 `state`。`--workspace` 是 id 或名称。名称匹配到不止一个工作区时失败，提示 `Several workspaces are named "<name>"; pass its id.` 没有匹配时提示 `No workspace matches "<name>". List the workspaces first.` `--role` 和 `--team` 二选一；两个都给会失败，提示 `Pass either an agent role or a team template, not both.` 任务是空的会失败，提示 `Describe the task to delegate.` `send` 和 `stop` 只接受这个助理委派过的会话。其他会话会失败，提示 `No work session you delegated has this id.`

```bash
cocurdex routine list [--persona <persona>]
cocurdex routine show <routine>
cocurdex routine create --persona <persona> --name <name> (--prompt <text>|--prompt-file <path>) (--every <minutes>|--at <HH:MM> [--days <mon,wed|weekdays|weekends>]) [--tz <zone>] [--access read-and-draft|full] [--deliver inbox|push|silent]
cocurdex routine update <routine> [--name <name>] [--prompt <text>|--prompt-file <path>] [--every <minutes>|--at <HH:MM> [--days <days>]] [--tz <zone>] [--access read-and-draft|full] [--deliver inbox|push|silent]
cocurdex routine pause|resume <routine>
cocurdex routine run <routine> [--wait] [--timeout <seconds>]
cocurdex routine runs [<routine>] [--limit <n>]
cocurdex routine delete <routine>
```

`--every` 和 `--at` 二选一。`--days` 需要 `--at`。`--access` 为 `read-and-draft`（默认）或 `full`。`--deliver` 为 `inbox`（默认）、`push` 或 `silent`。`routine runs` 列出每次运行的状态、开始时间和摘要。`--json` 还会带上 `outcome` 和 `question`。

```bash
cocurdex inbox
cocurdex inbox read <item-id>
cocurdex inbox brief [--tz <zone>]
cocurdex inbox brief post [--tz <zone>] [--locale en-US|zh-CN]
```

`inbox` 列出需要你处理的事项。`inbox read` 把该项的线程标为已访问，从而把它从列表里清掉。`inbox brief` 打印今日简报；没有内容时打印 `Nothing to brief today.` `inbox brief post` 把这份简报按你传入的语言贴进默认助理的主线程。`--locale` 为 `en-US` 或 `zh-CN`；省略则沿用上次发布所用的语言。没有新内容可发布时打印 `Nothing new to post.`

```bash
cocurdex apps catalog|list [--json]
cocurdex apps add <notion|linear|github> --name <name> [--assistants <id,id>] [--delegated] [--json]
cocurdex apps update --stdin [--json]
cocurdex apps check|tools|logout|remove <connection-id> [--json]
cocurdex apps login <connection-id> [--json]
cocurdex apps login-wait|login-cancel <connection-id> --login <id> [--json]
cocurdex apps login-return <connection-id> --login <id> --stdin [--json]
cocurdex apps read|call <connection-id> --tool <name> --stdin [--json]
```

`catalog` 打印 Notion、Linear 和 GitHub。`add --name` 是连接名称。`--assistants` 是用逗号分开的助理 id。`--delegated` 打开**允许委派工作使用**。未知应用会失败，提示 `Choose notion, linear, or github`。`update`、`login-return` 和 `read` / `call` 从标准输入读 JSON。把凭据写在参数里会失败，提示 `Pass the update JSON through --stdin; never put credentials in command arguments.` `login` 开始授权。`login-wait` 等待那次开始返回的 login id。`login-return` 从标准输入读完整的回调地址。`read` 调用提供方声明为只读的工具。`call` 是一般调用。两者都把工具参数作为 JSON 从标准输入读入。`remove` 打印 `{ "removed": true }`。`update` 的对象包含 `id`、`revision`、`displayName`、`personaIds`、`allowDelegatedWork` 和 `enabled`。GitHub 连接还可以带 `clientId`、`clientSecret` 和 `callbackPort`。

对应的产品 skill 是 [`cocurdex-persona`](/zh-cn/docs/skills/)。这些助理的记忆见[记忆](/zh-cn/docs/memory/)。
