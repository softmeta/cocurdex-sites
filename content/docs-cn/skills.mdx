**产品 Skills** 教会 Agent 如何使用 Cocurdex 的笔记、Issue、演示文稿和产品知识流。Skill 名称以 `cocurdex-` 前缀做**命名空间隔离**，避免与其他全局 skills 冲突。

Skills **不会自动安装**。从**设置 → 连接**里的 **Skills** 页安装，或使用 CLI。

**设置 → 连接**里的 **Skills** 页也管理产品包以外的 skill。**发现**会搜索 skills.sh。也可以读取一个 GitHub 仓库（`owner/repo` 或 URL）或这台电脑上的文件夹，再选择要安装的 skill。已安装的 skill 可以打开为**预览**或**源码**；预览被截短时，页面会提示打开文件查看其余内容。**检查更新**和**查看更新**会先列出变更的文件，再由你决定是否应用。**移除**会从每个能看见它的 Agent 上删除这个 skill，并在 `skill-backups` 下保留 14 天的备份。**恢复**把你本地改过的 Cocurdex skill 还原成内置副本。

窗格较宽时，已安装列表和**发现**都是列表与详情并排。窗格较窄时只显示列表。选中一行后，详情占满窗格。**返回列表**回到列表。

## 安装

```bash
cocurdex skills list
cocurdex skills status --scope project
cocurdex skills install --scope project
# 或安装到 ~/.agents/skills
cocurdex skills install --scope global
```

| 范围 | 含义 |
| --- | --- |
| `project` | 安装到工作区的 `.agents/skills`（`--root` 默认为 `cwd`） |
| `global` | 安装到 `~/.agents/skills` |

托管安装会写一个标记文件，以便 Cocurdex 更新或移除自己的 skill 包。更新托管安装时，已从包中移除的 skill 也会被删除，旧名字不会残留。如果同名 skills 已存在但**没有**该标记，安装会报告冲突——重命名或移除冲突目录后重试。

```bash
cocurdex skills remove --scope project
```

## Agent 从哪里找到 skills

**设置 → 连接**里的 **Skills** 页，以及 Claude Agent、Codex、OpenCode 和 ACP Registry Agent 在输入框里的 `/` 菜单，使用同一套目录解析。`CLAUDE_CONFIG_DIR`、`CODEX_HOME` 和 `XDG_CONFIG_HOME` 在这两处都生效，所以自定义 `CODEX_HOME` 下的 skill 会同时出现在设置里和 Codex 的 `/` 菜单中。Pi 的 `/` 菜单来自 Pi 运行时。

| 位置 | 共享 | Claude | Codex | OpenCode |
| --- | --- | --- | --- | --- |
| 用户主目录 | `~/.agents/skills` | 已设置时为 `$CLAUDE_CONFIG_DIR/skills`，否则为 `~/.claude/skills` | 已设置时为 `$CODEX_HOME/skills`，否则为 `~/.codex/skills` | 已设置时为 `$XDG_CONFIG_HOME/opencode/skills`，否则为 `~/.config/opencode/skills` |
| 工作区 | `.agents/skills` | `.claude/skills` | `.codex/skills` | `.opencode/skills` |

OpenCode 读取共享、Claude 和 OpenCode 这三列，包括工作区里的 `.claude/skills`。它在用户主目录下的 OpenCode 目录是 `~/.config/opencode/skills`（或 `$XDG_CONFIG_HOME/opencode/skills`）。这份列表里没有 `~/.opencode/skills`。

| Agent | `/` 菜单的检查顺序，从前到后 |
| --- | --- |
| Claude Agent | 共享（主目录）、Claude（主目录）、共享（工作区）、Claude（工作区） |
| Codex | 共享（主目录）、Codex（主目录）、共享（工作区）、Codex（工作区） |
| OpenCode | 共享（主目录）、Claude（主目录）、OpenCode（主目录）、共享（工作区）、Claude（工作区）、OpenCode（工作区） |
| ACP Registry Agent | 共享（主目录）、共享（工作区） |

同名 skill 出现在多个目录时，菜单采用最后检查到的那一份。每个 Agent 的工作区目录都排在它的主目录之后，所以工作区里的 skill 会替换同名的用户级 skill。

## Skill 目录

| Skill | 用途 |
| --- | --- |
| `cocurdex-note` | 通过 CLI 创建、更新、关联笔记——包括 PRD 和技术 spec |
| `cocurdex-issue` | 创建、列出、移动和细化 Issue;「todo」「ticket」「backlog」也会触发它 |
| `cocurdex-deck` | 创建和修改[演示文稿](/zh-cn/docs/decks/)，检查并导出 PPTX 或 PDF。以 `/cocurdex-deck` 调用 |
| `cocurdex-ship` | 实现一个 Issue 或 spec 笔记，运行项目检查，并推进 Issue 的状态列。需要你显式调用，Agent 不会自行启动 |
| `cocurdex-team` | 领导 [Agent 团队](/zh-cn/docs/teams/)：判断何时需要团队、给队友下达简报、合并报告 |
| `cocurdex-settings` | 通过 `settings_*` Agent 工具查看与修改应用和项目设置 |
| `cocurdex-persona` | 通过 CLI 创建并与[助理](/zh-cn/docs/assistants/)对话，管理它们的例行任务，并把仓库工作交给一个工作会话。以 `/cocurdex-persona` 调用 |

todo、ticket、backlog item 都指 **Issue**——同一个池子，不是独立的追踪器。

<Callout title="已下线的 skill">
早期的 skill 包还包含 `cocurdex-ask`、`cocurdex-grill`、`cocurdex-prd`、`cocurdex-spec`、`cocurdex-todo`、`cocurdex-ticket`、`cocurdex-link` 和 `cocurdex-layout`。它们有用的部分已并入 `cocurdex-note` 和 `cocurdex-issue`;重新安装或更新 skill 包会移除这些旧目录。
</Callout>

## 推荐的产品流程

```text
/cocurdex-note   (把 PRD 或 spec 写成笔记)
  → /cocurdex-issue  (拆分成 Issue)
  → /cocurdex-ship   (实现一个 Issue)
```

| 步骤 | Skill | 写入 |
| --- | --- | --- |
| 需求与设计 | `/cocurdex-note` | 私有笔记（PRD、spec、自由记录） |
| 看板工作 | `/cocurdex-issue` | 经 `cocurdex issue …` 写 Issue |
| 实现 | `/cocurdex-ship` | 代码 + Issue 状态更新 |

演示文稿在这条循环旁边。`/cocurdex-deck` 通过 `cocurdex deck` 写入。

## 隐私默认值

PRD、spec、笔记、Issue 和演示文稿都是**私有的应用数据**。打开项目文件夹**不等于**授权把产品文档写进 `.cocurdex/` 或 Markdown 树；把笔记发布到仓库需要明确的导出操作。

Issue 结构操作（列表 / 创建 / 移动 / 校验）始终经由：

```bash
cocurdex issue …
```

Skills 不得编造 issue id,也不得通过手工编辑文件改写状态。

## 在会话中使用 skills

聊天模式的 **+** 菜单没有 **Skill**，`/` 菜单也不列出 skill。工作和助理的输入框仍有这两处。

1. 安装 skill 包（project 或 global）。
2. 启动一个 Agent 会话。Claude Agent、Codex、OpenCode 和 ACP Registry Agent 从[Agent 从哪里找到 skills](#agent-从哪里找到-skills)里的目录加载 skills。
3. 用你的 Agent 支持的 slash 形式调用(例如 `/cocurdex-issue`)，在**工作**或**助理**的输入框里输入 `/`，或从该输入框的 **+ → Skill** 菜单中选择。
4. 通过 **+ → Issue** / **+ → 笔记** 附加 Issue 或笔记：Agent 会在提示词中直接拿到完整内容，skill 无需再次读取。

你的环境中可能还有其他非产品 skills(`tdd`、code review 等)；产品知识工作应留在 `cocurdex-*` 这一组里，以保证数据边界正确。
